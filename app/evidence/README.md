# M5 local artifacts

`LocalArtifactStore` keeps one immutable job directory per `testSpecId`. Each job has a versioned manifest, validated TestSpec, effective profile metadata, and separate attempt, resolved-spec, run, and evidence records. Writes stage complete files before an atomic no-overwrite link; job creation stages the whole directory. A later exploration attempt or execution run gets a new ID. The report reader rebuilds the source-to-attempt-to-resolved-step-to-run chain from disk, without a browser.

The initial retention setting is seven days (`retentionDays` on the store); the manifest records `expiresAt`. M5 does not delete artifacts automatically. Access control and expiry enforcement are M8 operational work.

M8-B enforces expiry on reads and provides an explicit `pruneExpired()` sweep for expired jobs and interpretation records. The sweep validates job identity and containment before removing a job; callers must invoke it as part of operations. The artifact root must be a private directory. On permission-aware hosts, an exposed root is refused; Windows deployments must enforce the root ACL externally because Node file modes do not provide that guarantee. Raw binary evidence is unavailable through the store unless a deployment-owned `RestrictedEvidenceAccess` gate authorizes its descriptor. Metadata reads remain redacted and integrity checked. The store is an internal component; external artifact serving requires its own authenticated boundary.

Text/JSON evidence is redacted for named secret literals, bearer values, sensitive keys, and common secret URL parameters. Executable TestSpec and ResolvedTestSpec contracts are rejected if they would require redaction, so their meaning never changes silently. Screenshots, traces, and videos cannot be reliably scrubbed as bytes. They require explicit `sensitiveBinaryApproved` capture policy, are marked `restricted`, and receive owner-only filesystem permissions where supported. Keep the artifact root outside public serving and protect it at the OS/deployment boundary. Traces and videos are retained only on failed runs when enabled; final screenshots are captured when enabled. The runner remains responsible for step semantics and the M3 factory remains responsible for browser policy and cleanup.

`executeAndStoreRun` is the M5 adapter: it reads accepted artifacts, passes observation callbacks to the M4 runner, captures permitted evidence, and persists the typed outcome. It does not resolve targets, modify locators, or perform MCP exploration.
