# Deferred Action Grounding WP2B: native options and trusted ownership

WP2B adds a private native-select option primitive to the completed WP2A candidate/binding foundation. The deferred grounding decision and semantic-fidelity addendum govern the implementation. Source meaning still comes from actual trusted ActionGoal v2 semantic admission; browser facts cannot rewrite it. No production workflow, provider call, public-target browser workflow, model strategy loop, witness/trace/compiler/resolved/runner route or label/general relationship primitive was introduced.

## Boundary and implementation

The missing fact was not an `option` role count. It was a complete list of the **selected control's** options, with executable values and protected owner provenance, followed by a fresh action-time proof of that same association. A displayed option in another control and copied snapshot prose cannot provide this fact.

`app/domain/action-option-grounding.ts` introduces strict `ActionOptionObservationV1` and `ActionChoiceActionCheckV1` schemas and integrity readback. `ActionCandidateGroundingSessionV1` gains additive `enumerateNativeOptions`, `withNativeChoiceBinding`, `protectedOptionRecord` and `protectedChoiceActionCheck` methods. They share WP2A's private session owner, trusted admission, candidate journal, binding journal, MCP exclusive guard, current frame/node proof and state epochs. The existing WP2A method and schemas remain unchanged; its original `select_option` path still rejects pending membership.

The option observation contains the complete parent candidate observation and issued binding, admitted choice obligation ID and exact authored choice, capture/expiry times, witness digest, and complete native option list. Each entry records a runtime option ID and index, owner binding/ref/frame, native membership, browser displayed label, native option text, executable value, effective disabled state and current selected state. The complete result also records whether the native control permits multiple selection. Profile/fingerprint, source/admission/mapping digests, attempt/session/page, frame ancestry and state/mutation ownership are inherited explicitly through the linked parent evidence. The integrity parser checks those links, owner/index/count consistency, native capability and inherited lifetime. Schema validity or a recomputed digest grants no issuance authority.

Native properties are read in Playwright's isolated utility world through fixed runtime-owned `contentScript` selector engines. One engine returns the actual bounded `HTMLSelectElement.options` node collection. A second creates a detached text carrier containing bounded JSON of native `option.label`, `option.text`, `option.value`, `option.selected`, effective `option`/parent `optgroup` disabled state, and the native owning-select relation. The carrier is transport only, never inserted into the document and never used as target or snapshot evidence. Runtime consumes it using protected Playwright text readback and a closed schema. Actual option handles are retained separately for frame, order and node identity rechecks. This avoids main-world page overrides of `options`, `closest` and option getters, and avoids reimplementing browser text normalization or treating raw text/value as displayed label.

No locator field is exposed in either new contract. The internal engine names and fixed browser queries are trusted implementation details; M7 cannot supply CSS, XPath, JavaScript, selector engines, DOM values or a caller `approved` flag. MCP tool schemas/inventory are unchanged.

## Complete enumeration and choice mapping

This package conservatively requires an **already unique WP2A-issued control binding**. It does not enumerate an arbitrary ref or use options to discard other candidate controls. WP2A's complete all-current-frame eligible role/name domain must remain unique during the protected renewed query. Two controls containing the requested option stay ambiguous unless admitted, reviewed constraints already disambiguate them. Later complete whole-predicate composition across several candidate controls belongs to WP2D; this API does not claim that broader composition.

Enumeration includes every option in the native `select.options` collection, including placeholders, disabled options and options inside `optgroup`. An empty complete option list is a valid fact. It is not proof that the requested choice exists. Bounds are 80 options, 1,024 UTF-16 code units per label/text/value and 262,144 code units for the protected JSON transport. An 81-node overflow sentinel bounds collection reads if the list grows between reads; it can never become a complete usable enumeration. Observations and action checks are each bounded to 80 session records, with WP2A's existing cooperative 15-second browser-read budget and profile/browser timeouts.

`complete: false` records carry `RESULT_LIMIT`, `QUERY_UNEVALUABLE`, `STALE_STATE` or `UNSUPPORTED_CONTROL`, with **no count or partial option list**. Query/ownership/state failures before option capture yield a typed grounding stop. No error, truncation, failed native ownership or stale record can establish option uniqueness. Option evidence inherits the original binding expiry, at most ten seconds from its candidate observation; reads that cross that deadline reject before issuance or consumption. It never extends an old binding's lifetime.

At action check, the trusted runtime requires exactly one option whose **displayed label equals the admitted authored choice**, with no trimming, case folding, synonyms or value-as-label substitution. It also requires exactly one option in the whole owned collection with that executable DOM value. Duplicate values reject even if only one displayed label matches or the other equal-valued option is disabled: selecting by value must not authorize a different sibling. A disabled matching option rejects. A unique empty DOM value is legitimate and supported. These checks produce `OPTION_ABSENT`, `OPTION_NON_UNIQUE`, `VALUE_NON_UNIQUE` or `OPTION_DISABLED` as runtime/grounding stops, never QA verdicts.

The source argument `Option 1` remains the choice obligation; it never becomes an accessible control name. The DOM value is derived by the runtime, not taken from source or model output. An accepted exact target-name mapping such as `Country` can narrow the control predicate independently; authored context, role synonyms, associations and relationships remain pending unless separately implemented and endorsed.

## Protected action-time lease

`withNativeChoiceBinding` requires the exact session-issued option observation and binding, not a schema-valid replacement. It renews the complete WP2A candidate query, proves one candidate, the selected frame/ref and original control node, rereads the complete owned native collection, proves unchanged option nodes/order/labels/values/disabled/selected states and native multiplicity, and checks current visibility/enabled state and operation compatibility. The unchanged state is captured again, and lifetime is checked immediately before issuing the protected check and invoking the trusted consumer.

Only the admitted choice's previously pending literal mapping can be realized by this primitive. Any other pending material obligation blocks action. `ActionChoiceActionCheckV1` includes the fresh option observation, parent option observation ID, selected runtime option ID, derived executable value, `select_option`, complete realized obligation IDs with an empty pending list, and fresh control/label/value uniqueness facts. Its protected journal readback grants origin authority; the schema/digest alone cannot.

The binding is single-use and invalidated after every attempt, including rejection and a callback that fails after partially changing selection. Once the trusted callback starts, its execution/environment/cancellation errors propagate unchanged; only pre-action query failures are normalized as grounding query stops. MCP calls attempted concurrently while the lease holds reject under WP2A's existing exclusive guard.

## Exact WP2D handoff

WP2D must retain the actual in-process trusted semantic admission, immutable accepted ActionGoal v2 obligations and complete WP1 handoff, total reviewed/endorsed mapping, complete runtime-issued candidate observation and unique binding, complete issued native option observation, and matching protected option/action-check readback. It must preserve source/admission/mapping and profile/session/page/frame/state ownership throughout later witness/trace assembly.

For native choice, WP2D must call `enumerateNativeOptions(binding)`, then invoke `withNativeChoiceBinding(binding, observation, trustedConsumer)`. The consumer must execute the reviewed native `select_option` **immediately inside the exclusive callback**, on the supplied frame-owned locator using the check's exact `executableValue`. It cannot execute against a global ref, another control, caller-supplied value or cached detached check. It must requery/rebind after any preparatory wait, retry or asynchronous actionability wait. Auto-waiting does not preserve whole-predicate uniqueness.

The check is pre-action evidence, not an execution or successful-effect witness. WP2D must account for actual/partial execution, including propagated consumer failures, and acquire a **fresh post-action observation** proving the intended option/value selected in the same fully source-constrained control. Failed attempts and abandoned candidates must stay outside successful trace evidence. The fixture verifies such fresh selected-state readback by creating a new candidate/binding/option observation after selection; WP2B does not assemble that into a witness or trace.

Browser script may still mutate the world after a final read. This lease coordinates trusted MCP consumers and detects observed drift; it is not an atomic browser transaction. Later action integration must preserve fresh pre/post checks, fail closed on operation/ref failure and avoid an unbounded wait between checking and acting.

Accessible custom listbox/combobox ownership is unsupported. The architecture defines no reviewed general relation sufficient to promote `aria-controls`, snapshot adjacency or an `option` role into option-to-control authority. Label association, general relationships and independent semantic mapping endorsement remain later packages.
