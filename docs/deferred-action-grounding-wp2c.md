# Deferred Action Grounding WP2C: trusted accessible label association

WP2C adds complete, runtime-owned label-to-control facts to WP2A's admitted-source candidate domain. The deferred grounding architecture and semantic-fidelity addendum remain authoritative. This package does not select a production workflow, call a provider, implement general relationship/containment semantics, expand custom option ownership, execute an M7 strategy loop, or introduce trace/compiler/resolved/runner versions.

## Boundary and implementation

The missing fact was an actual semantic association between an authored designation and its current eligible control. Nearby text, snapshot adjacency, a control's name alone, and model claims cannot establish that association. `app/domain/action-label-grounding.ts` adds closed `ActionLabelAssociationRequestV1`, `ActionLabelAssociationObservationV1`, `ActionLabelAssociationBindingV1`, and `ActionLabelAssociationCheckV1` contracts and integrity parsers. The existing `ActionCandidateGroundingSessionV1` gains additive `queryLabelAssociations`, `bindLabelAssociation`, `withLabelAssociationBinding`, `protectedLabelAssociationRecord`, and `protectedLabelAssociationCheck` methods. MCP tool inventory and model-callable schemas are unchanged.

A request contains only its version and an accepted obligation ID. The actual in-process WP1 v2 admission supplies the exact authored text and source obligation. The parent must be a complete, session-issued WP2A candidate observation with total source-obligation accounting. The runtime does not accept supplied label text, `approved`, CSS, XPath, JavaScript, locator language, another session's observation, or a schema-valid replacement with a recomputed digest.

`app/exploration/action-label-semantics.ts` registers fixed Playwright utility-world engines. Native `control.labels` plus `label.control === control` establishes explicit `label for` and wrapped-label ownership. For `aria-labelledby`, the runtime retains the complete active set of document-resolved IDREF nodes. Native getters and DOM ID resolution are isolated from page-world overrides. A detached bounded JSON carrier transports the active relation kinds; it is never inserted into the page, used as target evidence, or presented as snapshot text.

Positive text correspondence uses Playwright's exact `getByLabel` predicate, separately from native/IDREF ownership. `exact: true` uses Playwright's case-sensitive browser label text matching and whitespace normalization. Authored source bytes remain unchanged in admission and observation; no English parsing, synonyms, word replacement, or source trimming determines the mapping. The observation retains every node in the active owned source group rather than choosing an arbitrary source by DOM order. It does not claim that each individual source node equals the whole authored designation.

Per-target snapshots replace Playwright's active aria-ref subtree. Consequently, the runtime refreshes the full current page/frame registry after renewed complete enumeration and verifies unchanged state before reading all controls. Every selected ref remains separately checked against its actual original control node. This fixes a new multi-control integration issue without changing WP2A enumeration or binding contracts.

## Completeness, ownership, and conservative limits

The primitive scans **every control in the entire issued WP2A predicate domain across all current frames**. It cannot inspect one convenient ref and claim that no other associated control exists. Complete observations carry the full association count and list, actual accessible-name metadata, an equality flag that compares that metadata with the authored designation, all owned label/IDREF source IDs and relation kinds, and explicit control ref/frame ownership. Complete zero is a valid absence fact; it grants no binding or discharged pending label obligation. Two associated eligible controls remain ambiguous. A single label referenced by two controls likewise gives count two.

Multiple distinct labels on one control are supported: exact `Country` can identify that control while its actual name metadata is `Country Region`. Equivalent multiple labels are retained as one complete source group for their common owner. Neither case silently turns the authored label into the control's whole accessible name. The same source group must survive current-node rechecks. IDREF resolution uses the browser's actual `Document.getElementById` result, including its defined first document-resolved node for duplicate IDs; no alternate same-ID element is treated as interchangeable. Removing/replacing/reordering the resolved source invalidates prior evidence.

The reviewed initial text predicate is deliberately conservative. `aria-label` alone has no separate owned label node in this primitive. If it matches the authored label on any eligible control, the whole query stops `UNSUPPORTED_CONTROL` rather than dropping that control and manufacturing uniqueness. Shadow-root association, combined IDREF text that exact `getByLabel` cannot evaluate as one label, image-alt alternatives, and nested ARIA text alternatives likewise stop unsupported. A role/name match never substitutes for label contribution; it can only identify an unresolved text-alternative edge and force an incomplete stop. A nearby name/title/value cannot fabricate an association. These limits leave deeper AX contribution semantics for a separately reviewed browser primitive.

Bounds are WP2A's 80 candidates, eight current frames, 512 UTF-16 code units of authored label text, at most 16 active label/IDREF sources per control, a 4,096-code-unit facts transport, and 80 session observations, bindings, and checks each. The existing exclusive grounding lease provides a cooperative 15-second query budget; the helper checks it and inherited observation expiry before/after each browser read and each source iteration. Facts transport reads have a three-second per-read timeout. Observations/bindings/checks inherit the original WP2A observation expiry, at most ten seconds, and never extend it.

Incomplete records carry `RESULT_LIMIT`, `QUERY_UNEVALUABLE`, `STALE_STATE`, or `UNSUPPORTED_CONTROL`, with **no partial association list or usable cardinality**. An incomplete parent, unproved current frame, wrong source/session/page, changed profile ownership, browser error, stale age, MCP revision, navigation/state drift, source/control replacement, or changed association cannot establish uniqueness. Hidden controls are not removed from the eligible domain to make another control unique. If WP2A cannot issue a current ref for a hidden candidate, its query remains incomplete; if a hidden candidate is recorded, its association cannot produce an actionable binding. Disabled controls likewise cannot produce actionable binding.

## Obligation realization and protected current check

Only positive **target-owned** `name` or `context` constraints can request these facts. A reviewed exact target designation (`name`) may be realized by a unique exact associated-label predicate: this proves that authored designation identifies the control through its real label relation, without assuming whole accessible-name equality. The requested pending name obligation becomes realized only when the complete association count is one. Zero/two/error results preserve it as pending. Existing realized WP2A predicates retain their accounting.

Raw authored `context` is not a typed label obligation. Even an exact corresponding label fact leaves that context obligation **pending** until a bounded independent semantic endorsement validates its proposed label realization against immutable source/obligations. This package does not create that endorsement or expose a caller discharge flag. `Country dropdown` cannot be shortened lexically to `Country`. Relationship obligations and anchor-owned constraints are unsupported by this request: `Email` in `button next to Email` cannot become a target name/label mapping.

The distinct label binding requires complete unique association, selected-ref membership, current frame ownership, live node identity and visibility/enabled state. Its protected fresh check renews the **whole original broad candidate domain**, every control identity, the association predicate, every active source identity/order/kind, unchanged state, and lifetime while holding the MCP exclusive guard. It is single-use, invalidated after every attempt, and records parent association, issued binding, fresh association observation, complete count one and selected-ref match. Consumer errors propagate unchanged after the trusted callback begins; they remain environment/automation outcomes, not QA failures.

This is association/readiness evidence, **not** complete authored-goal or action authorization. Its distinct contracts cannot enter WP2A's old `withActionTimeBinding` or WP2B's `enumerateNativeOptions`/native choice route. Pending arguments, contexts, references and relationships remain present. Protected journal readback grants runtime-origin authority; closed schema/digest validity alone does not. A check does not prove execution or a fresh post-action effect.

## Exact WP2D handoff

WP2D must retain the actual trusted WP1 semantic admission, immutable accepted ActionGoal v2 source obligations and full handoff, total reviewed/independently endorsed grounding mapping, issued complete WP2A candidate observation, complete issued WP2C association observation, its distinct issued binding, and protected current-check readback. Candidate admission/mapping digests remain unchanged: the WP2C request/observation is an explicit additional exact association realization, not a silent reinterpretation of a pending WP2A mapping. WP2D must incorporate that realization and every remaining obligation into its final full-predicate mapping and provenance digest.

The current sequence is `query(request)` -> `queryLabelAssociations(candidateObservation, { labelGroundingVersion: '1', obligationId })` -> `bindLabelAssociation(associationObservation, selectedRef, frameId)` -> `withLabelAssociationBinding(binding, trustedConsumer)`. The consumer receives a fresh, protected association check under the exclusive lease. It must not treat this detached check as a later action capability or forward a frame-local ref as a global MCP locator.

WP2D still owes reviewed composition of label association with all other endorsed predicates, including WP2B owned native option/unique value mapping for choice. The observation's narrower association set must not overwrite WP2A's broad domain or waive WP2B's old unique-control precondition. WP2D must build and renew the complete conjunction, ensure every material obligation is actually discharged, and prove one current actionable target at action time. For context translation it must obtain independent source-based semantic endorsement first; browser uniqueness cannot reinterpret source meaning.

After waits/retries/preparatory actions, WP2D must requery/rebind. It must execute only the reviewed operation on the exact current frame-owned control with the admitted/runtime-derived argument inside its protected integration, account for partial/failed execution, and capture fresh post-action effect evidence. This association package assembles no successful witness or trace. Browser script can mutate after a read: the lease coordinates trusted MCP consumers and detects observed drift, not an atomic browser transaction. Later witness/trace/compiler work must preserve the complete source predicate, state/frame chain and runtime origin, and exclude failed/abandoned candidates from successful evidence.

## Compatibility and validation

Production changes are an additive association contract/export, fixed isolated browser semantics helper, and additive methods/private journals in the existing WP2A session. WP2A/WP2B request/observation/binding/action-check schemas and existing behavior, TrustedObservationResult v1, old current-state bindings and witnesses, ActionGoal v1, earlier M7 decisions, and historical source/trace/compiler/resolved/runner routes are unchanged. There is no fallback, automatic upgrade, production cutover, credentialed provider call, or public-target browser workflow.

Focused tests use protected noncredentialed loopback contexts and the actual in-memory MCP client/server. They cover explicit/wrapped/native labels; single and multiple IDREF/native labels; separate actual-name metadata; duplicate label text/shared-source ambiguity; nearby/orphan/superseded text; zero domain; pending context; unchanged full authored context; anchor ownership; hidden/stale/replaced/wrong-frame/session evidence; forged association/check authority; native choice narrowing with choice still pending; page-world getter/ID resolution spoofing; bounds/query errors; renewed state/expiry drift; unsupported text alternatives and aria-label second controls; duplicate-ID actual source ownership; and propagated consumer errors.
