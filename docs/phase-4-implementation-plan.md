# Phase 4 implementation plan: interactive observability

## Objective and fixed baseline

The local, single-operator Streamlit PoC should show reviewed progress while the existing production workflow runs, then optionally show bounded browser images and a live view of the same protected browser. Deliver these capabilities in order: **P4-1 sanitized events**, **P4-2 periodic screenshots**, **P4-3 headed container with noVNC**. Each capability has its own release gate. A later capability cannot substitute for a failed earlier one.

The completed Phase 3 path remains Streamlit/Python → the supervised Node subprocess → real OpenAI interpretation and bounded Playwright MCP exploration → accepted `ResolvedTestSpec` → two fresh deterministic replays → Node-owned typed result and report. The [architecture](architecture.md), [TestSpec contract](test-spec-schema.md), [Phase 2 integration decisions](phase-2-integration-decisions.md), [subprocess v1 contract](p2-3-subprocess-protocol.md), [Phase 3 plan](phase-3-implementation-plan.md), [public admission contract](p3-a-public-admission.md), and [report projection v1](p3-b-report-projection.md) remain authoritative. The P3-F live proof returned `QA_ASSERTION_PASSED` in both replays with a correlated safe projection; its screenshot state was `capture_disabled`.

Current seams matter to the delivery order:

- `app/local/workflow.ts` calls `handoffTask` and owns the protected session lifecycle. `app/interpretation/handoff.ts`, `app/exploration/resolve.ts`, `app/exploration/mcp.ts`, and `app/runner/run.ts` have distinct interpretation, MCP, locator, and replay stages. `RunObserver` is an optional execution observer and cannot influence operation selection or locator binding.
- `app/subprocess/cli.ts` reserves stdout for **one final** protocol-v1 JSON result and discards general child stdout/stderr. `src/playwright_demo/host.py` supervises that exchange. Phase 3's opt-in safe terminal diagnostics are a troubleshooting aid, not an execution timeline or a Python state API.
- `app/evidence/capture.ts` permits final/failure binary capture only with trusted `sensitiveBinaryApproved`; `LocalArtifactStore` owns restricted evidence. `reportProjectionVersion: "1"` exposes screenshot *state and metadata*, never image bytes.
- The public browser runs in the disposable, no-host-mount, network-none compartment created by `app/profile/isolated-browser.ts`; trusted Node bridges its private Playwright control and authoritative proxy. Its current Chromium entry is headless. Existing headed profile semantics are versioned and observational: `autonomousEligible: false` regardless of detected input. A fresh headless run remains the autonomous proof.

The URL/task form never grants network access, changes trusted profile/capture settings, or chooses observability authority. `OPENAI_API_KEY` remains in the trusted host environment and absent from the browser compartment, request JSON, ordinary evidence, and UI state. Phase 4 adds observation paths, not another model, browser, locator, QA, or artifact authority.

## Architecture decision gates

Close each gate in a reviewed document before its dependent code package. A gate selects one concrete contract and failure policy; implementers must not infer them from a UI library or transport example.

### P4-G0 — Live event contract and transport (before P4-1)

**Decision owner:** architect reviewer with Node subprocess owner, Python host owner, and security reviewer.

Define a separately versioned **closed event exchange**, distinct from both subprocess protocol v1's final result and `reportProjectionVersion: "1"`. Choose a bounded, local, authenticated, per-run transport that supports events before the final result and works on Windows/PowerShell and the supported local runtime. A private host-created channel is the preferred design candidate; the review must establish its exact framing, endpoint ownership, authentication, ordering, buffering/backpressure, shutdown, and cleanup. General stderr text, arbitrary logs, report polling, and the final stdout document are not acceptable substitutes. Do not silently add frames to subprocess-v1 stdout. If the reviewed solution requires a protocol version change, document and version it explicitly, preserve the v1 caller, and prove compatibility.

Node constructs events from trusted stage transitions, permitted MCP **tool names** and outcomes, locator quality **reason codes**, result vocabularies, and generated correlation IDs. The proposed event envelope has a version, per-run monotonic sequence, bounded timestamp, closed event kind/stage/status/reason, profile fingerprint, and only applicable TestSpec/attempt/resolved/run/step IDs. The gate fixes exact required/nullable fields and limits. No model reasoning, provider body, snapshot, page text, task text, locator expression, tool arguments/results, URL query, arbitrary error message, credential, or restricted artifact reference may cross the channel. Python validates the entire closed envelope and sequence; Streamlit renders it but does not infer engine state from logs.

Specify what happens if the observer is slow, disconnects, misses events, or if the event channel fails. A bounded gap/unavailable indicator may be shown; the UI must never invent skipped stages. The final validated subprocess-v1 result remains the QA authority. Observation failure cannot turn QA pass into QA failure or silently grant broader browser/model authority. A security failure in channel setup must fail closed before engine work; the gate decides whether loss after start stops execution or degrades observation while preserving a trustworthy final result. Define cancellation/reaping of the event channel alongside the existing Node child.

**Exit:** Node and Python can implement compatible closed wire validators and a testable private transport, including non-success and disconnect behavior. A security review approves the field allowlist and confirms protocol-v1 compatibility.

### P4-G1 — Live screenshot capture and access (after P4-1)

**Decision owner:** evidence/backend architect and security reviewer with Python UI owner.

Define a separate versioned **live-image access contract**, not a new field or binary branch of report projection v1. Node alone captures from the active protected MCP or replay page. Decide whether images are ephemeral or separately stored as restricted evidence, how a request is correlated to the one active attempt/run and profile, who authorizes capture and read access, and how browser pixels are displayed locally without Python opening arbitrary artifact paths. A screenshot can contain secrets even when the event stream is sanitized; the gate must record an explicit trusted opt-in and sensitivity/retention policy. It cannot assume generic pixel redaction is reliable.

Set finite cadence, image dimensions, byte count, frame count, queue depth, total live lifetime, and cleanup limits; settle behavior during navigation, page closure, multiple sequential protected sessions, timeout, cancellation, and viewer disconnect. The UI must distinguish `capture_disabled`, `not_captured`, `temporarily_unavailable`, and an authorized frame without treating lack of images as an engine failure. No screenshot request may execute page scripts, select another browser, read report artifacts, or modify replay timing/steps. The gate decides whether capture overhead has a bounded fail-safe and how to prove it.

**Exit:** A reviewed restricted-byte mechanism, capture policy, and failure semantics are precise enough for Node/Python independent implementation. If authorized safe display cannot be established, P4-2 is blocked rather than exposing unrestricted evidence.

### P4-G2 — Headed compartment and private noVNC viewer (after P4-2)

**Decision owner:** architect reviewer and security engineer with Docker/browser owner and Streamlit owner.

Select the versioned headed execution profile and browser image/runtime changes needed for one virtual display, a view-only VNC/noVNC path, and the **same** isolated Playwright-controlled browser. Specify how the viewer reaches a per-run private endpoint while the compartment keeps no host mounts, no provider credentials, no direct egress, no published management port, the authoritative proxy, and lifecycle disposal. The UI and container must remain loopback-only and single-operator. The viewer must not expose CDP, proxy control, host files, or an unbounded file/clipboard/upload/download channel. Decide whether keyboard/mouse input is disabled at the viewer server as well as the UI; any detectable input remains observation evidence and never becomes a replay step.

Headed runs are observational with unverified physical-input provenance and always `autonomousEligible: false`. Preserve distinct headed/headless profile versions and fingerprints; do not mutate legacy profile semantics. A separate fresh headless run remains the autonomous-equivalence path. Define viewer authentication/token lifetime, origin/connection checks, cross-process ownership, disconnect handling, and forced-cleanup reporting. noVNC is optional observation attached to the protected session, never a second browser or a new execution engine.

**Exit:** The reviewed design includes a concrete private transport and fail-closed proof matrix for isolation, view-only access, profile identity, proxy path, credential exclusion, cleanup, and headless equivalence. If the compartment cannot keep those properties, P4-3 does not launch.

## Dependency order and critical path

```text
P4-G0 → P4-1A → P4-1B → P4-1C → P4-G1 → P4-2A → P4-2B → P4-2C
                                                            ↓
                          P4-D ← P4-3C ← P4-3B ← P4-3A ← P4-G2
```

P4-G1 can be *researched* while P4-1 is built, and P4-G2 can be *researched* while P4-2 is built, but their decisions and dependent code wait for the preceding capability's gate. This protects the order the product requested and lets P4-2 reuse the correlated event timeline for frame availability and P4-3 reuse both timeline and image-state presentation. Separate contracts can be authored in parallel only where ownership is explicit. The implementation critical path runs through the three security gates, the cross-process event integration, image authorization, the private viewer path, and the three manual real-provider proofs. No delivery date is credible until G0's transport and G2's viewer isolation feasibility are reviewed. Each package hands off a validated contract, working path, or recorded gate result rather than a percentage estimate.

P4-1's event IDs and attempt/run/profile correlation become the join key for P4-2 frame availability and P4-3 viewer lifecycle. They do **not** authorize image or viewer access. P4-2/3 each require separate trusted permissions and transports. A missing event never permits guessing that a frame or viewer belongs to another session.

## Validation and release rules

1. **Contract/security tests:** closed schemas on both sides, unknown-field denial, string/payload redaction, byte/rate/queue limits, correlation, version rejection, and malformed/duplicated/out-of-order frames. Page injection, model output, and MCP responses cannot create new event kinds, screen access, or browser authority.
2. **Credential-free end-to-end tests:** use the existing test-only injected-model subprocess seam, real Python/Streamlit host composition, fixed runner, two fresh replays, and protected browser/profile proofs where needed. Assert that live observation is consistent with the final v1 envelope and Node report. Cover denied public URL, proxy outage, forced termination, cancellation, and no residual viewer/container/process. An opt-in Docker test that skips is *unverified*, not passed.
3. **Manual live gates:** the human holds `OPENAI_API_KEY` in the launch environment, uses a freshly reviewed approved public target and exact profile, and returns only safe event codes/IDs, image/viewer availability state, fingerprint, typed QA outcome, two run IDs, report projection status, and cleanup result. P4-3 additionally requires a fresh headless run; a headed run cannot certify autonomy. Provider/site outages or absent credentials leave the corresponding manual gate unverified.
4. **Regression:** subprocess-v1 single final JSON and exit semantics, report projection v1, public admission v1, profile fingerprints, locator quality, deterministic replay, proxy-only egress, and Phase 3 loopback UI must remain green. No observation callback may mutate TestSpec, `ResolvedTestSpec`, runner steps, QA classifications, or network policy.

## Delivery risks and escalation triggers

| Risk / early signal | Mitigation, accountable escalation, contingency |
|---|---|
| Live events collide with subprocess-v1 stdout or Python infers state from stderr text | G0 selects a separate closed channel before 1A/1B. Node/Python owners block integration on extra stdout frames, unbounded stderr parsing, or incompatible v1 results; architect reviews a versioned alternative. |
| Event backlog or observer failure stalls model, MCP, or replay | G0 fixes queue/backpressure and loss semantics; 1B tests slow/disconnected consumers. Stop on unbounded memory or deadlock. Preserve truthful final result when the approved failure policy permits degradation; never fabricate a complete timeline. |
| Sensitive page/provider data leaks through event labels or image pixels | Node emits only enum fields; security reviews every added field. G1 requires explicit trusted capture/read approval and bounded lifetime. Disable capture when the page or deployment cannot meet the approved sensitivity policy. |
| Screenshot cadence changes replay or captures another session | 2A uses current protected-session ownership and attempt/run IDs; tests compare capture-on/off outcomes and enforce budgets. If timing alters QA or profile equivalence, halt 2C and reduce/disable capture pending review. |
| noVNC weakens the container boundary or creates a public management port | G2/3A prove network-none, no mounts/key, view-only private access, short-lived token, and disposal. Any exposed port, control input, direct egress, or unverified cleanup blocks 3B/3C and returns to security review. |
| Headed view is incorrectly labeled autonomous | 3B/3C assert headed `autonomousEligible: false` even with an empty input log. Use a separate fresh headless run for autonomous equivalence; block closure on contrary UI text or evidence. |
| Docker/display/real provider unavailable for a manual proof | Keep credential-free gates recorded separately; mark the affected capability unverified. Do not claim Phase 4 complete or substitute a mocked/provider-free run. Retry only after environment recovery or reviewed target reapproval. |

Escalate contract changes to architect/security review before implementation, runtime isolation failures to the Docker/Node/security owners immediately, and cross-process mismatch to the Node/Python owners before the next package. The project manager protects the critical path by recording gate evidence and refusing a downstream handoff without its preceding exit signal.

## Phase 4 exit and deferred work

Phase 4 is complete only when all three ordered capabilities pass their credential-free and manual live gates, the Streamlit UI shows a truthful live timeline, authorized bounded images, and an optional private noVNC view of the actual protected headed browser; the final typed QA result and two fresh deterministic replays remain Node-owned; a separate headless proof establishes autonomous equivalence; and all viewer/browser resources are cleaned up. Documentation and architecture/security closure must match observed behavior.

Still deferred: external or multi-user hosting, authentication/authorization platform, job queue/database, remote browser farm, arbitrary artifact browser/downloads, raw model or MCP transcripts, private reasoning display, general manual browser control, selector auto-healing, public internet wide-open egress, and `.spec.ts` export. Phase 4 does not make screenshot/noVNC access equivalent to `reportProjectionVersion: "1"` or create a standalone engine HTTP service.

This plan is ready for **architecture review**. P4-1 implementation starts only after P4-G0 closes its event contract and transport; the remaining decisions are deliberately sequenced after the preceding capability's release gate.
