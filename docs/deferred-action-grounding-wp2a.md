# Deferred Action Grounding WP2A: complete candidates and current-ref linkage

WP2A implements an additive private candidate/binding foundation against the deferred grounding decision and its semantic-fidelity addendum, after the completed WP1 v2 independent gate. It does not select a production workflow, implement a model strategy loop, execute a choice, or change trace/compiler/resolved/runner contracts.

## Boundary and correction

The prior trusted observation API can count unnamed roles but cannot link that complete count to the selected current action ref. The existing structured binding also requires the separately versioned v5 named intent. The new `ActionCandidateGroundingSessionV1` consumes the in-process trusted ActionGoal v2 semantic admission directly. Schema-valid source, copied admission JSON, digests, MCP snapshot prose and model claims cannot substitute for that authority.

`ActionCandidateRequestV1` is a strict data-only proposal containing the goal ID, the exact WP1 obligation handoff, and one mapping entry for every accepted obligation ID. Unknown fields, selectors, locator expressions, CSS, XPath, scripts, omitted/duplicated/substituted IDs and altered handoffs reject before a browser query. There is no caller/model `approved` flag.

The reviewed exact mappings are effect, explicit operation, literal preservation, a positive target role whose authored text is exactly one closed role identifier, a positive exact authored target name, and positive target uniqueness. These are finite typed correspondences, without English parsing or role synonym tables. Translating `dropdown` into `combobox`, authored context into containment, anchor text into a target name, or a general relationship into a browser predicate is not endorsed by this package. Such obligations must remain `pending`; an attempted exact mapping of the wrong kind/endpoint/value stops unsupported. Later independent semantic mapping endorsement is still required for inference beyond these exact mappings.

## Complete candidate semantics

The runtime constructs the entire eligible role domain from the admitted effect: activation uses the existing reviewed clickable role union; entry uses textbox and searchbox; choice uses combobox and listbox. Only an accepted exact target-role or target-name obligation can narrow that domain. M7 cannot supply a discovered name, a convenient role, a frame restriction, or a scope restriction to make an authored-open target look unique. The query covers **all current frames of the one protected page**. A second eligible control in another role or frame participates in the count.

The runtime enumerates exact semantic Playwright queries, including hidden matches. It obtains browser-computed semantic properties and actionability, and uses the AI JSON snapshot's ref solely as a correlation key. Membership is proved by intersecting the semantic candidate locator with its frame-local `aria-ref` locator, verifying one match and actual frame ownership. Snapshot text is never parsed to prove meaning, membership, role, name or uniqueness. Empty computed accessible names are supported. A candidate that cannot receive a trustworthy current ref causes an incomplete/error query rather than disappearance from the count.

`ActionCandidateObservationV1` records the request/predicate, admission/mapping digests, realized and pending obligation IDs, profile/fingerprint, attempt/session/page, frame identities and unique title/test-ID ancestry, state/mutation epochs and digest, capture/expiry times, and runtime-owned witness digest. `realizedObligationIds` records closed realization and candidate-predicate correspondence; it does **not** assert that an effect or operation was executed. If obligations remain pending, `complete: true` describes the broad candidate predicate only, not complete fulfillment of the authored goal. Pending material can never gain action authority through browser uniqueness.

A complete result contains the full count and full candidate list, bounded to 80, with schema/readback count consistency and unique frame/ref pairs. Zero is a complete fact and stops `NO_CANDIDATES`; two stops `NON_UNIQUE`. Exceeding the candidate bound gives `RESULT_LIMIT`, with `complete: false` and **no count**. Query failure, state drift and unproved frame ancestry similarly produce no usable cardinality. No truncation, error, hidden/unlinkable candidate or partial list can establish uniqueness. The runtime also bounds frames to eight, iframe siblings to 80, frame ancestry to eight, document/snapshot sizes, and observations/bindings/action checks to 80 each. Grounding reads check a 15-second cooperative deadline between bounded browser reads; browser read/action timeouts still bound the in-flight operation. A failure before a state record exists produces a typed runtime stop, never a zero-match record.

## Ephemeral binding and action-time evidence

`ActionCandidateBindingV1` is issued only by this runtime after validating a still-current complete observation and proving that the selected frame/ref belongs to its unique candidate set. A matching serialized digest is insufficient: issuance/readback must match this session's private journal. Bindings expire with the candidate observation after at most ten seconds. Replacement runtime, closed browser, navigation/frame/page drift, source/profile mismatch, wrong session, changed state, forged records and ref substitution reject.

The shared MCP session has an additive call revision and exclusive grounding guard. Every started/completed MCP tool call, including snapshots, failed calls and actions with no DOM effect, invalidates previously observed state. While a grounding query/bind/action callback holds that guard, a concurrent MCP call rejects rather than crossing the current-state proof. Existing tool inventories and schemas are unchanged.

`withActionTimeBinding` revalidates the issued binding, reruns the entire complete predicate, proves count one, selected ref/frame and the same actual DOM node, checks visible/enabled/editability and admitted operation compatibility, and captures a second unchanged state before invoking the trusted consumer. The second-target regression injects a candidate between initial freshness checking and renewed enumeration; the callback never runs. The callback receives a fresh, privately journaled `ActionCandidateActionCheckV1`, not an old observation presented as action-time evidence. It records the parent observation/binding, complete fresh candidate proof, admitted operation and exact authored argument. The binding is single-use and invalidated even if the callback fails.

This is a trusted code integration seam, not a model-callable function or detached action capability. `ActionCandidateActionCheckV1` proves a current pre-action check, **not execution or a fresh post-action effect**. Choice literal preservation remains pending until option/control ownership and unique label/value mapping exist; `select_option` is explicitly blocked here. Context, relationship, reference and prerequisite mappings likewise remain pending. No general association primitive or semantic endorsement is fabricated.

## Required WP2D handoff

WP2D must consume the actual trusted semantic admission, complete WP1 handoff and immutable source obligations, total endorsed mapping, runtime-issued candidate observation and binding, and protected action-check readback. It must preserve the candidate predicate's complete domain and every accepted obligation. It must introduce reviewed evidence/independent semantic endorsement for pending mappings; a smaller candidate set or a unique browser ref is not a substitute. This package offers no caller API to mark pending IDs discharged.

For an executable supported mapping, WP2D must invoke the reviewed action inside `withActionTimeBinding`'s exclusive trusted callback, using the supplied frame-owned locator and exact admitted operation/argument. The local ref must not be forwarded as a globally unique MCP ref across frames. No cached action-check object may authorize a later action. Trusted consumers must not run browser mutations concurrently outside this lease; they must act immediately after the protected recheck and account for every attempted/partial mutation. Browser page script can still change the world after a read; ref/node identity checks and operation failure must remain fail-closed, and later strategy work must preserve fresh pre/post checks rather than claiming an atomic browser transaction.

WP2D must requery/rebind after an asynchronous preparatory wait, retry, or actionability wait rather than consuming a cached pre-action check. Playwright action auto-waiting does not preserve the complete semantic candidate predicate by itself. Its closed action integration must guard against ref-only execution bypassing renewed full-predicate uniqueness. WP2D must then record actual execution and fresh observed effect, full obligation/argument/association correspondence, frame/state chain, and runtime-owned protected journal linkage for the later witness/trace package. A pre-action check cannot be promoted into a successful action witness. The current record schemas/digests permit integrity readback; only protected runtime readback grants origin authority. Later trace work must correlate these records at capture/execution, preserving failed/abandoned candidates outside the successful trace.

Only additive domain/exploration exports and private MCP coordination were introduced. No production selection or automatic upgrade was added. No provider workflow ran; browser fixtures used noncredentialed protected loopback contexts and the actual in-memory MCP client/server.
