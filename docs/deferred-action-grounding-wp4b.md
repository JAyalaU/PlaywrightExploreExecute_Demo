# Deferred Action Grounding WP4B: two fresh replays and external projection

## Boundary and agreement

`app/interpretation/deferred-action-replay.ts` composes the unchanged authenticated WP4A handoff. `runDeferredTwoFreshReplaysV1(factory, actualV9Readback)` authenticates the actual `TrustedResolvedTestReadbackV9`, invokes runner v9 sequentially using that same capability, and receives only actual `TrustedDeferredRunV9` records. Each runner invocation owns a new protected browser context, session, page identity and run ID; it completes cleanup before a second run starts. No browser storage or session state is shared. The runtime does not import any model, exploration, MCP or SDK module and does not perform retry, discovery, repair or historical-runner fallback.

`app/domain/deferred-action-replay.ts` mechanically validates exact test/source-admission/trace/compiler/resolved/profile linkage, ordered source/trace step IDs, operation/argument and assertion shape correspondence, distinct replay/session/page IDs, compiler/exploration session separation, completed ordered path, time boundaries and record digests. Parsing cannot issue runtime authority. Both completed runs with verified cleanup are required before agreement is established. A first runner stop ends the package without launching a second run. A later second-run stop preserves the first run and its successful action/effect evidence.

Agreement compares each corresponding VerificationGoal's ordered execution/source/trace IDs, exact deterministic assertion shape, full actual value and evaluated boolean. Aggregate `passed` alone is never an agreement criterion. Equal observations with all true evaluations produce QA pass; equal observations with any false evaluation produce QA fail. True/false differences, different actual values even when both evaluate false, or different corresponding failures hidden by an equal aggregate false produce non-QA reproducibility failure. Both zero-assertion completions establish reproducible execution only: `EXECUTION_REPRODUCED / NO_ASSERTIONS`, with no QA verdict.

A runner non-QA stop remains non-QA even after prior assertions or successful mutations. Cleanup uncertainty produces the environment overlay `SESSION_CLEANUP_FAILED`. A factory-open rejection before any session is issued remains an environment stop with verified no-resource cleanup, matching the unchanged runner contract. A missing approved profile similarly stops before context creation; presentation defaults to headless administrative metadata only in that no-browser stop and does not claim a proved effective profile. A changed available profile is checked by runner v9 before browser launch. An unexpected runner exception is recorded as host environment uncertainty with unverified cleanup; it never causes retry.

## Result, origin and storage

`ResultRecordV2` gains the isolated `deferred-action-v1` workflow family and required `deferredReplay` linkage: source v6/contract2, trace5, compiler4, resolved9, runner9, source/admission/trace/compiler/resolved/pair digests, pair ID, ordered run digests and available session IDs. Successful QA, reproducibility, and assertion-free execution require two distinct run/session identities and verified cleanup. Historical workflow records reject deferred linkage and cannot use the assertion-free terminal.

`TrustedDeferredReplayV1` uses private symbol plus WeakSet issuer origin. Copied data, prototype objects, constructor calls and schema-valid forged records cannot authorize persistence. `app/evidence/deferred-replay-store-v9.ts` stores restricted full records and their exact derived ResultRecordV2 in the separate immutable `deferred-replay-v9-result-v2` namespace. Writes require actual runtime pair origin plus actual authenticated v9. A restricted per-root HMAC key authenticates the envelope, including source owner, exact v9 digest, pair, runs and terminal. The store checks regular bounded files, rejects symlink/path escape, writes asynchronous exclusive temporary files and installs them without overwrite. No synchronous filesystem I/O or dependencies were added.

`readReplayV1(testSpecId, orchestrationId, actualV9Readback)` re-authenticates the envelope, mechanically validates the complete pair against that actual v9, and independently derives the terminal again. It returns only actual `TrustedDeferredReplayReadbackV1`. The reader imports pure contracts and authenticated store helpers; its runtime issuer import occurs only during write. `requireTrustedDeferredReplayReadbackV1` checks genuine private issuer origin before returning cloned records. The authority is the trusted host-owned root and its restricted keys, matching WP3 stores; an attacker who already controls that authority root is outside this boundary.

Persistence validation rejects substituted or dropped provenance, changed assertion/argument correspondence, reused sessions or runs, continuation after a stopped first run, incomplete pairs, and inconsistent digests/terminal. HMAC verification rejects on-disk substitutions even if their JSON schema looks valid. Result records expose correlation digests and identifiers only; full step/effect/assertion data stays restricted.

## Safe projection and historical isolation

`app/subprocess/deferred-report-projection-v2.ts` provides `projectDeferredReportV2(actualPairReadback)`. Its separate closed projection-v2 contract exposes only the derived ResultRecordV2, replay IDs and bounded completed/stop classification, assertion counts, cleanup, reproducibility, and optional authoritative QA. It exposes no source text or arguments, browser values or actual assertions, guard predicates, semantic mappings, locators, traces, protected records, screenshots or private errors. Even QA outcomes with numeric/boolean assertions withhold actual/expected values. The response is bounded to 8192 bytes and two replays.

The closed projection checks correspondence to result run IDs and rejects contradictory QA, assertion-free execution, or reproducibility classification. Projection parsing is serialization validation only; actual authenticated readback is mandatory to produce a trusted projection. The existing `envelopeForAgenticTerminalV2` accepts the version-aware ResultRecordV2. Assertion-free execution is a typed non-QA automation envelope with the explicit execution terminal, never a success envelope.

Historical ResultRecordV2 records, old result finalization, old report reconstruction, and compiler/runner families remain separate. The historical LocalArtifactStore terminal writer and reader explicitly reject deferred-family records, and its historical report projector returns REPORT_UNAVAILABLE before reconstruction. A valid historical job/profile plus a valid deferred-family envelope regression proves those guards; a new result cannot accidentally enter the trace2/3/4 reconstruction branch. Existing trusted local/CLI/Python workflow selection does not select `deferred-action-v1`. This package does not modify Python/Streamlit workflow routing or their external enums. New external-family integration and acceptance of this projection belong to reviewed cutover work after the independent WP4B gate.

## Exact cutover handoff

After the independent WP4B gate, a separately reviewed trusted workflow host may:

1. Authenticate trace5 with `SuccessfulTraceV5Store`, then obtain actual v9 through `DeferredCompilerV4Store.readResolvedV9(testSpecId, compilerAttemptId, actualV5Readback)`.
2. Call `runDeferredTwoFreshReplaysV1(protectedFactory, actualV9Readback)` from `app/interpretation/deferred-action-replay.ts`. No caller-supplied run/result/approved fields are accepted.
3. Persist actual pair via `DeferredReplayV9Store.writeReplayV1(actualPair, actualV9Readback)` and keep exact artifact/pair/run links. A store failure is an external persistence/environment stop; it cannot promote the pair to QA or trigger repair.
4. Obtain the authenticated derived result with `requireTrustedDeferredReplayReadbackV1`, and bounded safe output with `projectDeferredReportV2`. Reopen through `readReplayV1` with the same authenticated v9 if needed. Use the existing `envelopeForAgenticTerminalV2` only after immutable terminal persistence.
5. Separately review production trusted selector, v6 interpretation and v5/compiler4 integration, Python wire/projection validators and UI support for the deferred version linkage and explicit assertion-free execution terminal. Do not route the new artifact through an old store/projector or compiler/runner. No production cutover has occurred here.
