# Deferred demo runtime budget

The gated `deferred-action-v1` demo now allows each of its two sequential, independent provider extractions up to **180,000 ms**. The shared interpretation cap is **420,000 ms**: 360,000 ms for both full provider-call allowances plus 60,000 ms for local normalization, source validation, and admission. A late provider completion still stops at its own per-call boundary. Parsing and normalization after a timely provider-client completion use the shared cap. The independent source-first call still receives only the original source and reviewed contract; no retry or fallback was added.

The enclosing Python `call_node` host accepts at most **900,000 ms**. The trusted UI path previously passed its default 300,000 ms to that host, which could terminate deferred interpretation before the new shared cap. When trusted launch configuration selects `deferred-action-v1` and the existing `offline-review` gate permits it, `run_ui_workflow` now defaults to **900,000 ms** for the Node engine call. An explicitly supplied host deadline remains an override subject to `call_node` validation. Legacy, released agentic, goal-directed, and structured-action workflows still default to 300,000 ms. Admission lookup and read-only projection retain their own separate bounds. The demo host cap leaves up to 480,000 ms after a maximally long interpretation for grounding, compilation, two replays, and persistence; those stages retain their own limits.

Private interpretation timing validation now accepts the 420,000 ms shared limit. Test-only override bounds remain finite (at most 240,000 ms per extraction and 600,000 ms shared). The existing payload-free timing and structural diagnostics, cancellation precedence, stage-specific non-QA stops, and stakeholder-safe result/projection contracts are unchanged. No prompt, model, semantic rule, browser grounding, verification, or workflow-selection gate changed.

Focused validation: deadline tests 8/8, interpretation and structural compatibility 37/37, targeted WP5A host/persistence tests 2/2, and affected Python deferred/UI/host tests 28/28 passed. Typecheck and build passed. All provider behavior was mocked; a separately authorized live run is still needed to measure actual provider latency and full-path completion under this budget.
