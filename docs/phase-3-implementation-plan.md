# Phase 3 implementation plan: local Streamlit PoC

## Objective and baseline

A stakeholder enters a public HTTP(S) URL and a natural-language UI test task in a local Streamlit application, starts one run, sees honest execution status, and receives the typed QA outcome and useful, authorized evidence. The production path remains Streamlit/Python → `playwright_demo.call_node` → the versioned Node subprocess entry → real OpenAI and bounded Playwright MCP exploration → accepted `ResolvedTestSpec` → two fresh deterministic Playwright replays → Node-owned report and evidence. Streamlit is a thin, loopback-only, single-operator host, not another execution engine.

Phase 2 and its public-web acceptance gate are complete. The [architecture](architecture.md), [TestSpec contract](test-spec-schema.md), [Phase 2 integration decisions](phase-2-integration-decisions.md), [P2-3 subprocess protocol](p2-3-subprocess-protocol.md), and [public-web closure record](public-web-acceptance-plan.md) govern Phase 3. Existing profiles, fingerprints, result categories, locator quality, browser isolation, and deterministic replay remain authoritative.

Two current limits prevent a truthful arbitrary-public-URL UI today:

1. `PublicTargetApprovalSchema` admits only the exact Columbia and Challenging DOM URLs. The public profile/policy carries fixed destination hosts and DNS pins, and `runLocalWorkflow` requires an exact approved start URL. A URL field cannot itself authorize a new host, port, address, redirect, or secondary request.
2. Subprocess protocol v1 returns one final typed envelope with report availability and correlation IDs. It emits no progress stream or assertion details. Its report reference does not grant Python access to Node-owned artifacts. The current public production configuration disables screenshot capture; restricted image bytes require separate capture and access approval.

Phase 3 must close the first limit before claiming general public-URL support. It must close the second only to the extent needed for useful, safe result presentation. A page that needs denied secondary traffic may still stop under policy; the UI must explain the typed outcome without silently granting that traffic.

## Decision gates

### P3-G0 — General public-target authority

**Owner:** architect reviewer and security engineer; network engineer and Node profile owner review feasibility.

**Scope:** Define a reviewed way for a locally submitted HTTP(S) URL to receive explicit, bounded public-target approval without editing source code or preparing a hard-coded profile for each site. Decide who can approve a local submission, what constitutes trusted host configuration, how Node validates or creates the approved profile/policy without transferring policy authority to Python, and how approval binds the exact start URL to an immutable versioned profile/policy and fingerprint across exploration and both replays. If admission needs another subprocess exchange, version that contract rather than silently widening v1. Resolve HTTP versus HTTPS ports, DNS answer validation and drift, redirects, secondary hosts, disallowed/private/reserved addresses, URL credentials, IP literals, and failure on unenforceable policy. A submitted URL or page request must never directly mutate policy. Preserve the disposable browser-only container, proxy-only egress, credential exclusion, and no direct fallback. State the supported public-URL envelope, the typed denial behavior for sites that cannot be safely admitted, and how that state appears in the local UI.

**Exit:** Architecture/security decision records a practicable local approval flow that accepts user-supplied public URLs without a site-specific code change, names its trusted authority, and specifies repeatable exact-profile G1 proofs. If no such flow meets the existing invariants, block the advertised arbitrary-URL PoC before UI integration; a one-target dropdown is not completion.

### P3-G1 — Safe report and evidence presentation

**Owner:** architect reviewer and evidence/security owner; Python host owner reviews the consumer contract.

**Scope:** Decide the smallest Node-owned read-only projection needed to show assertion expected/actual, per-run status, and safe evidence descriptors from a correlated stored report. The v1 subprocess result remains a final summary and report reference; do not silently add fields or raw evidence bytes to it. Specify a versioned or separate bounded retrieval contract, caller authorization for the local PoC, correlation and path checks, redaction, size limits, and behavior when a report is absent or expired. Screenshots may be displayed only when trusted capture policy enables them and the existing restricted-evidence access boundary authorizes the read. If that is not approved, show the available safe report summary and omit image display explicitly.

**Exit:** Node and Python owners can implement the same closed presentation contract without granting Python arbitrary artifact-file access or changing QA semantics.

The two decision gates can run in parallel. Architecture review of their outputs is required before implementation that depends on them.

## Dependency order and critical path

```text
P3-G0 ── P3-A ────────────────┐
      └── P3-C ───────────────┼── P3-D ── P3-E ── P3-F ── P3-G
P3-G1 ── P3-B ────────────────┘
```

G0 and G1 can be reviewed in parallel. After their contracts close, A, B, and C can proceed in separate fresh specialist sessions; D is the integration join. The critical path is the slower of public-target authority/isolation and safe evidence presentation, then D → E → manual F → G. No date estimate is credible until G0 proves a feasible general-public admission model and the live site remains reachable. Each package hands off a reviewed contract, implementation, or recorded proof rather than a claimed percentage complete.

## Risk controls and escalation

| Risk or early signal | Control and escalation trigger |
|---|---|
| Static exact-target approval is presented as arbitrary URL support | G0 decides the new trusted admission contract before UI release. Block D/F if a newly entered public host still needs a code change or if URL input itself grants egress. |
| Dynamic DNS, redirects, or page secondary traffic bypasses policy | A preserves request-by-request proxy checks and exact effective-profile identity; deny unapproved destinations. Escalate any direct-egress or profile mismatch to security/architecture review; never add hosts merely because a page requests them. |
| Public browser reads host files or provider credentials | A/E repeat container and credential-sentinel proofs on admitted public profiles. Stop live proof on any isolation, proxy, or disposal regression, including an unverified forced cleanup. |
| UI labels a spinner as engine progress or a process failure as QA failure | C/D show only host-owned pending state before the final v1 envelope and render every discriminant separately. A need for live stage events triggers a separately reviewed protocol change, not inferred status. |
| Report reference becomes an arbitrary file read or screenshot leak | G1/B require correlated Node-owned projection and restricted-byte authorization. Omit screenshots if access approval is absent; stop release on raw paths, secrets, or unbounded content. |
| Provider or public site is unavailable during live proof | E closes independently with injected-model coverage; F remains unverified. Requalify another public target under G0 rather than broadening policy or declaring an injected run live. |

## Explicit boundaries and completion

Streamlit and Python own the local form, process supervision, and rendering of validated outcomes. The Streamlit UI binds only to loopback for one local operator and rejects externally reachable launch configuration. Node continues to own input validation, OpenAI/MCP orchestration, profile/network approval enforcement, locator acceptance, deterministic replay, QA classification, artifact storage, report reconstruction, and cleanup. Provider credentials never enter the task envelope, Streamlit state, or ordinary evidence. The PoC does not add an HTTP engine service, remote/multi-user hosting, authentication, a queue/database, unrestricted agent behavior, noVNC, or `.spec.ts` export.

Phase 3 closes only when the reviewed general-public-URL capability, safe evidence boundary, UI workflow, credential-free regressions, and human-operated real-provider proof have passed and are documented. The plan is **ready for architecture review**, not authorization to implement G0's undecided security semantics.
