# Agentic production external outcome mapping decision

Status: reviewed contract decision implemented for the agentic-v2 local workflow. This document remains the authoritative mapping for agentic outcomes. The legacy workflow, `ResultRecord`, subprocess protocol v1, report projection v1, and P4 event stream v1 retain their existing schemas and behavior.

Implementation and release status: the separate `ResultRecordV2`, subprocess-v2 parser/envelope, and read-only report-projection-v2 reconstruction are implemented. The trusted Node agentic CLI composes interpretation, WP4B execution, immutable v2 terminal storage, and the separate projection-v2 CLI; the Python/Streamlit host selects those entries only for trusted `agentic-exploration-v1` jobs. Legacy v1 entries remain separate. The credentialed seven-step Status Codes release proof completed with two agreeing fresh deterministic replays and `QA_ASSERTION_PASSED`; see [the completed release record](agentic-v2-release-gate.md). Agentic P4-1 terminal events remain unavailable pending separate review. An early exploration stop without a persisted successful trace carries a safe terminal with `report: unavailable`.

## Scope and decisive evidence

`runAgenticProductionV1` now composes TestSpec → bounded exploration → immutable trace v2 → fresh protected compiler → accepted v6 → two fresh replay runs. Its private `AgenticOutcomeV1` has exploration, compilation, replay, QA, environment, and cleanup boundaries. The current `ResultRecord` permits only `interpretation | exploration | locator | execution` phases; its closed statuses have no compilation, reproducibility, cancellation, or environment terminal. Subprocess v1 has only `qa_failure | automation_stop` typed-stop kinds and `not_started | exploration | replayed` progress. Its safe reasons omit several agentic stop codes. Report projection v1 accepts only a validated subprocess-v1 result and reconstructs legacy attempts/resolved v2–v5/runs; it does not read trace/compiler/v6 linkage. Python strictly validates those v1 vocabularies and currently renders all non-QA typed stops as “Automation stopped.” Therefore mapping every agentic terminal into v1 would erase the distinctions required by the product or misuse a legacy reason/status. A generic `REDACTED_REASON`, `TEST_BUILD_FAILED` for every compiler problem, or `QA_ASSERTION_FAILED` for a failed replay is not an acceptable substitute.

The smallest honest migration is a **parallel agentic external contract**: `ResultRecordV2` terminal summaries, subprocess `protocolVersion: "2"`, and `reportProjectionVersion: "2"`, selected only for a trusted `agentic-exploration-v1` job. Legacy jobs continue to use the existing v1 wire and projection without reinterpretation. The v2 exchange retains one bounded request/one bounded response, strict Node/Python validation, launch-owned profile/credentials, and a separate read-only Node projection. It does not create an API service. The request continues to carry only task, URL, and profile reference; workflow selection is trusted launch configuration, fixed before creating the TestSpec, and is never a form/wire task field.

## Closed public vocabulary

`ResultRecordV2` is a **terminal summary** separate from existing runner step `ResultRecord`s. It has a version literal `resultVersion: "2"`; closed `stage`, `status`, `reason`; TestSpec ID; optional attempt, trace, compiler, resolved, and up to two run IDs; exact approved profile reference/fingerprint; cleanup state; and no artifact path or unrestricted value. The stage is one of `interpretation`, `exploration`, `compilation`, `replay`, `reproducibility`, `qa`, `environment`, `cancellation`. Status is one of `INTERPRETATION_FAILED`, `AMBIGUOUS_INSTRUCTION`, `EXPLORATION_UNRESOLVED`, `EXPLORATION_UNSUPPORTED`, `COMPILATION_FAILED`, `COMPILATION_UNSUPPORTED`, `REPLAY_BINDING_FAILED`, `REPLAY_WAIT_FAILED`, `REPLAY_EXECUTION_FAILED`, `REPRODUCIBILITY_FAILED`, `QA_ASSERTION_PASSED`, `QA_ASSERTION_FAILED`, `ENVIRONMENT_FAILED`, `CANCELLED`. Status/stage combinations are closed by validation; `QA_ASSERTION_*` is legal only at `qa` after two matching completed fresh replays. Existing step `ResultRecord` status/reason data remains private until Node projects an approved bounded subset.

Safe v2 reason codes are the closed union of the codes used below; do not pass arbitrary `reasonCode` or provider exception text. The new codes relative to subprocess v1 are `BUDGET_EXHAUSTED`, `UNSAFE_RECOVERY`, `UNSUPPORTED_OPERATION`, `UNSUPPORTED_CAPABILITY`, `BROWSER_UNAVAILABLE`, `PROFILE_MISMATCH`, `POSTCONDITION_MISMATCH`, `COMPILER_ENVIRONMENT_UNAVAILABLE`, `REPLAY_ENVIRONMENT_UNAVAILABLE`, `REPLAY_OUTCOMES_DISAGREE`, `REPLAY_EXECUTION_FAILED`, `CANCELLED`, `LINK_COUNT_MISMATCH`, and `LINK_DESTINATION_MISMATCH`. Existing subprocess-v1 safe codes reused with their existing meaning include `TARGET_NOT_FOUND`, `PROVIDER_ERROR`, `PROVIDER_TIMEOUT`, `MODEL_ERROR`, `MODEL_TIMEOUT`, `NETWORK_POLICY_DENIED`, `SESSION_CLEANUP_FAILED`, `UNSUPPORTED_GRAMMAR`, `WEAK_IDENTITY`, `NON_UNIQUE_MATCH`, `TARGET_MISMATCH`, `FRAME_RESOLUTION_FAILED`, `WAIT_CONDITION_TIMEOUT`, `NO_MATCH`, `AMBIGUOUS_MATCH`, `NOT_VISIBLE`, `TEXT_MISMATCH`, `VALUE_MISMATCH`, `URL_MISMATCH`, `EVALUATION_FAILED`, `UNKNOWN_TIMEOUT_POLICY`, and `REDACTED_REASON`. Where the current private implementation has only a broader reason, use that broader safe code; it must not claim a narrower diagnosis. For example, `UNSAFE_RECOVERY` may be emitted only after a reviewed internal branch establishes that exact stop. Any private reason outside this allowlist becomes `REDACTED_REASON` in the v2 terminal and safe projection; its stage/status and QA boundary remain intact. Node and Python must validate the same closed set.

V2 subprocess response has the same high-level `success | typed_stop | bridge_error` separation but a closed `terminal` equal to the v2 summary's stage/status/reason and a closed `stopKind`: `automation_stop | environment_stop | reproducibility_stop | cancelled | qa_failure`. A `success` is legal only for authoritative `QA_ASSERTION_PASSED`; `qa_failure` only for authoritative `QA_ASSERTION_FAILED`. The v2 `progress` discriminator is `not_started | exploration | compilation | replay` and carries only identifiers already persisted at that stage. `replay` permits one or two distinct run IDs, so failure between runs never invents the second ID. `cleanup` is `not_started | verified | unverified` on every terminal envelope; a forced host kill remains a separate Python process failure with `cleanup: unverified`. A v2 report reference is available only after Node verifies the corresponding private persisted data. Node and Python must reject impossible stage/progress/ID/stop-kind combinations and mismatched response/exit status. Preserve current byte limits and independent stderr handling unless a separate reviewed bound change proves necessary. V2 must not be emitted to a v1 consumer; version negotiation is explicit at trusted launch, and old consumers reject v2.

V2 report projection accepts only a validated v2 result and reconstructs the exact Node-owned source, approved profile/fingerprint, attempt, trace v2, compiler attempt, accepted v6 if any, and zero/two independently persisted replay runs according to progress. It exposes opaque correlation IDs (not paths or retrieval capabilities), terminal, observation/headed provenance, a closed stage summary (`not_started | completed | stopped`, with the same safe reason), per-run closed state (`not_started | completed_pass | completed_fail | automation_failed | unavailable`), optional authoritative QA **only** for a matching completed pair, cleanup, bounded reviewed step outcomes, bounded evidence descriptors, and screenshot availability. It must keep v1 limits or fail `REPORT_TOO_LARGE`; never silently truncate. It excludes successful trace contents, failed/recovery branches, compiler candidate locators/check details, frame paths, MCP/provider output, raw page text, URLs, developer diagnostics, hashes, artifact paths, and restricted bytes. Strings in assertion expected/actual remain withheld; numeric/boolean/null values follow the v1 safe-value rule only for authoritative replay assertions. Projection failure cannot change the validated subprocess result. P4-1 events must not reuse v1 terminal semantics for v2: either hold the agentic UI timeline unavailable until a reviewed v2 terminal correlation is added, or introduce a separately versioned event terminal; do not infer stage from stdout/stderr.

## Exhaustive terminal mapping

In the matrix, `S2` means one validated subprocess-v2 envelope with the stated terminal and stop kind; `P2` means the read-only projection-v2 stage summary when the corresponding private records pass correlation, otherwise `unavailable`. `—` means absent. `R0/R1/R2` are zero/one/two persisted replay IDs, never fabricated. `N` means no authoritative QA verdict. `Y` means a verdict exists only after two agreeing completed replays. Terminal expected/actual are **always absent**. P2 may show safe per-assertion values only for a Y row. All rows carry the actual cleanup state from verified disposal (`V`) or uncertainty (`U`); forced termination always U. The stage-specific source and reason must be verified from trusted records, not model text.

`path_established`, compiler `accepted`, and replay `reproduced` are **nonterminal stage facts**; they never become standalone QA success. P2 may mark these stages completed after exact private correlation. Cleanup `verified` is a provenance fact, never a QA result. Cleanup `unverified` is a failure overlay as above. For a provider or integrity exception that is not safely classified by trusted code, the Node adapter emits a non-QA bridge/runtime failure, never a fabricated internal reason.

For any compiler or replay failure outside the enumerated reason allowlists, retain the verified public stage/status and emit `REDACTED_REASON`; do not forward a private string or borrow a misleading code. A verified compiler rejection with an unknown safe subtype remains `COMPILATION_FAILED`, while an unverified compiler exception remains an environment/bridge failure. This fallback never turns an automation stop into a QA failure.

## Required normalization and report rules

The findings below describe gaps identified while this decision was reviewed.
The agentic-v2 implementation and credentialed release gate now cover the
required mapping and report behavior; see [the release record](agentic-v2-release-gate.md).
These constraints remain normative for future changes.

The private `AgenticOutcomeV1` alone is too coarse to choose every row: use its boundary/status **and** the trusted stage and closed reason. Current WP4B maps exploration `environment_failed` and `cancelled` to private `path_unresolved`; correct that before public projection. Current controller maps several target/recovery problems to `TARGET_NOT_FOUND`, and MCP tool errors other than policy denial to `BROWSER_UNAVAILABLE`; preserve these coarse facts unless a reviewed internal diagnostic distinguishes them. Do not emit `UNSAFE_RECOVERY` or a provider-specific code by guesswork. Current compiler can throw on source/profile mismatches before persisting a rejection and WP4B catches only a compiler environment error. Production cutover must convert these to a verified rejected compiler attempt or a non-QA environment/integrity error before claiming a compilation row. Current replay catch uses `REPLAY_ENVIRONMENT_UNAVAILABLE` with cleanup `unverified`; do not claim verified cleanup from the run store alone. A mismatched pair may contain a per-run assertion pass/fail, but the terminal has no QA verdict.

Node must build one private terminal summary after all stage/cleanup checks, validate it, and persist or reconstruct it against the exact source and stage artifacts before emitting S2. It must never synthesize fake `ResultRecord` step results to satisfy legacy `readStoredJobReport`. For agentic P2, read the agentic trace/attempt/compiler/v6/run stores through a separate bounded Node reconstruction branch, verify every ID and fingerprint, and include only reviewed safe fields. The compiler attempt is allowed as an opaque correlation ID; its raw checks/locator provenance are not projected. On an early stop with no reportable persisted record, `report: unavailable` is honest and the v2 terminal still carries safe category/reason. A projection unavailable response never changes QA classification.

## Cutover implementation and validation record

1. Add closed `ResultRecordV2`, subprocess-v2, and report-projection-v2 schemas/parsers in Node and Python; keep all v1 entrypoints and legacy consumers unchanged. Reject cross-version requests/responses and unsafe/unknown reasons. Preserve host cancellation, bounded graceful shutdown, forced `cleanup: unverified`, response/exit correlation, loopback UI, and strict profile checks.
2. Select `legacy` or `agentic-exploration-v1` once from trusted launch configuration before interpretation; freeze it for the job. Do not put it in the user request or grant fallback after agentic failure. Wire the agentic model adapter and WP4B composition through the existing protected factory/observation lifecycle. Headed results stay `observational` and `autonomousEligible: false`; a separate fresh headless workflow establishes autonomous proof.
3. Normalize the private stop reasons, persist an exact terminal summary, and add the Node-only report reconstruction branch. Ensure an accepted v6 and two distinct run IDs are required for a QA terminal; permit one run ID for a partial replay stop; never claim a compiler rejection without a stored attempt.
4. Update the Python host/UI only for validated v2 fields. Render seven clear categories: agent path unresolved, compilation failed after path success, replay could not reproduce, replay disagreement, QA passed, QA failed, and environment/cancellation. Show stage IDs/status with no raw artifacts. Keep v1 rendering unchanged. P4-1 terminal correlation must be reviewed/versioned or declared unavailable for agentic jobs; P4-2 image and P4-3 viewer authority do not follow from S2/P2.
5. Validate one full headless Status Codes path through S2/P2, one exploration stop, one persisted compiler rejection, replay binding/wait failure, pair disagreement, true/false assertions, provider/policy/cancellation/forced-cleanup failures, tampered correlation, mismatched versions, bounded projection denial, legacy v1 compatibility, and headed observational status. Credential-free coverage passed; the operator-reported real-provider Status Codes run completed trace v2 compilation and two agreeing fresh replays with an authoritative QA pass, as recorded in [the release record](agentic-v2-release-gate.md).

**Decision and status:** ResultRecord's existing unversioned terminal vocabulary is insufficient; agentic jobs use a separately versioned terminal record. Subprocess v1 and report projection v1 remain unchanged for legacy. The local host selects the parallel v2 contracts and Node/Python validate and present them. The credentialed real-provider release gate is complete as recorded in [the agentic-v2 release record](agentic-v2-release-gate.md). The agentic P4 terminal timeline remains deferred pending its own correlation review.
