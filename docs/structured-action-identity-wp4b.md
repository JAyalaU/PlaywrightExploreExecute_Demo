# Structured action identity WP4B: production orchestration

The trusted `structured-action-v1` selection routes one job through TestSpec v5, protected M7 action binding with `ActionIdentityWitnessV1`, SuccessfulExplorationTrace v4, fresh compiler attempt v3, immutable ResolvedTestSpec v8, and two separate fresh deterministic v8 replays. ResultRecordV2 and report projection v2 remain the public contracts. The request payload cannot select the workflow; the trusted Python host passes its selected version through the Node subprocess environment before interpretation. An invalid v5 interpretation or any later structured stop has no v4/v3/v7 or v2/v6 fallback.

The v5 exploration controller reuses the bounded M7 action and VerificationGoal decision loop, but selects the protected v4 trace assembler and v4 immutable storage. Protected current-state binding proves each authored target against its structured intent before action. Discovered prerequisites retain their separate runtime identity and cannot complete an authored step. The v4 compiler consumes only structured intent/witness and fresh semantic correspondence, without the historical authored-language parser. Accepted v8 input is minted after immutable store readback; the v8 runner receives no authored action text or model/MCP authority.

Each replay call independently reads the accepted artifact, opens and closes a new protected browser context, and stores an ordered run linked to v8. The production route runs the calls sequentially, with distinct run IDs and the same approved profile/fingerprint. Matching completed true assertions classify `QA_ASSERTION_PASSED`; matching completed false assertions classify `QA_ASSERTION_FAILED`. Different completed signatures, including pass/fail or completed/automation differences, stop at reproducibility. Matching unevaluable/automation results and environment failures remain non-QA. Exploration and compilation never classify QA.

Finalization and read-only projection independently read the version-specific v4 trace, compiler attempt v3, resolved v8, and persisted runs. They check TestSpec/profile/attempt/trace/compiler/resolved/run linkage and reproducibility before exposing a terminal result. Private action witnesses, observation records, strategy details, raw model output, and restricted evidence are not copied into ResultRecordV2 or the safe projection.

Offline Add/Remove integration covers successful and false verification paths, two fresh replay contexts with verified cleanup, replay disagreement and matching automation stops, exploration and compilation stops, tampered provenance, no cross-version fallback, and no model/MCP below accepted v8. Historical `goal-directed-v1` v4/v3/compiler-v2/v7 and released `agentic-exploration-v1` v2/v6 routes remain separately selected. An independent security/integration release gate and approved-public-target real-provider proof are required before release status is claimed.
