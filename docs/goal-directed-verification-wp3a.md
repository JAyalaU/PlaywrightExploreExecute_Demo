# Goal-directed verification: private M7 reasoning WP3A

WP3A is a **private in-memory** verification controller. It consumes validated TestSpec v4 `verification_goal` steps and the WP2 `TrustedObservationSessionV1` in the same protected attempt. It does not write SuccessfulExplorationTrace v3, compile assertions, run deterministic QA, or change ResultRecordV2/subprocess/projection contracts. The released v3 action controller and v2 trace path remain unchanged. A later package must connect this private journal to trace v3 and the production orchestration boundary.

## Decision v4 and loop

`AgenticVerificationDecisionV4` is a closed union. `observe` contains exactly one `TrustedObservationRequestV1`: semantic query, unique-target property, current URL, or model-facing semantic snapshot. `conclude` contains `satisfied`, `unsatisfied`, `unresolved`, or `unsupported`, plus one optional typed comparison. The OpenAI Structured Outputs wire is `agentic_verification_decision_v4`; optional query name/scope and comparison use `null` on the wire and are removed before strict parsing. The v3 action decision and wire are separate.

The controller supplies the authored goal, ordered trusted results, bounded prior successful observations, and the trusted action ordinal to M7. M7 can request several observations, inspect their results, and choose a comparison. One successful observation does not complete a goal. A conclusion is accepted only after the controller locates every operand in its own current request/history records, calls WP2 `currentEvidence()` for the latest fact, checks type, subject, scope, completeness, attempt/session/page/state provenance, and evaluates the comparison itself. A model claim of the opposite result becomes `unresolved`. Error results and snapshots are never comparison operands. Snapshot text may guide another query but cannot prove absence.

Comparison v1 has one closed operation: complete match count versus integer (`equal`, `greater_than`, `at_least`, `at_most`); unique-target boolean state; unique-target text/value or protected current URL versus an authored literal; or a two-observation `appears`/`disappears` transition. It has no code or arbitrary logical tree. Comparison meaning must agree with the TestSpec intent hint when present. For an unhinted goal, only direct authored count/property/temporal wording or a literal text/value/URL condition can authorize that comparison. This comparison is an **exploration fact**, not a replay assertion.

An evaluated false condition is `unsatisfied` and can have a successful strategy journal entry. It is not `QA_ASSERTION_FAILED`. `unresolved` means intent, target, evidence, or freshness is insufficient; `unsupported` means the reviewed observation language cannot express the condition. Visual/spatial “above” has no WP2 primitive, so the controller cannot validate an order claim. Both outcomes omit a successful strategy entry.

For disappearance, the earlier complete query must have observed a positive count and must already belong to a successful prior verification strategy. The later complete query must use the same semantic query, observe zero, and pass current-evidence validation. Both records must have the same attempt/session/page; the later state epoch and protected action ordinal must advance. A final zero count alone is insufficient. The trusted action ordinal advances only when the caller presents an actual changed-state action fact in the current-state action journal.

## Budgets and journal

Each goal permits at most 12 model decisions, 8 observations, 2 snapshots, 30 seconds elapsed, 8 seconds per model call, 4,096 response characters, and 28,000 model-context characters. Identical requests with unchanged current evidence stop as `NO_PROGRESS`; stale evidence can be re-observed within the per-goal bound. Budget and provider failures produce non-QA `unresolved` results. The WP2 session retains its own stricter observation limits.

`SuccessfulVerificationStrategyV1` is a closed, private, in-memory record. It contains the goal step ID; ordered observation IDs and compact typed request/results; protected witness, frame, session/page/state/epoch/time correlations; the bounded comparison; evaluated boolean; M7 conclusion; action ordinal; and an integrity digest. The parser checks digest and ID/result alignment. The journal contains only successfully evaluated `satisfied` or `unsatisfied` goals. Failed queries, abandoned attempts, model prose, and chain-of-thought stay outside it. It is not persisted as a trace or exposed by the public result protocol.

## Integration boundary

The WP3A controller shares the protected `CurrentStateExploration` owner with WP2 observations. Action steps still use current-state bindings; verification queries do not use action bindings. Protected fixture tests alternate action steps and VerificationGoals, including Add/Remove Elements, without changing the released action authorization code. The private controller and OpenAI v4 adapter are available to the future trace-v3 orchestration package. Production `runAgenticExplorationV1` still finalizes only v2 traces and therefore does not yet invoke this controller for TestSpec v4 goals.

The exact next dependency is a reviewed SuccessfulExplorationTrace v3 assembler/store that consumes this validated journal, orders it with action facts across state transitions, verifies each observation witness against protected source facts, and persists only a successful strategy. That assembler will then allow production M7 orchestration to hand off goal-directed paths to a fresh compiler-attempt v2. No deterministic replay or QA verdict follows from WP3A alone.
