# Structured action identity WP4A: deterministic v8 runner

`executeResolvedTestSpecV8` is the dedicated private entry point for an accepted `ResolvedTestSpec` v8. It accepts only a runtime-authenticated `AcceptedResolvedTestSpecV8` capability, not raw TestSpec, trace, or resolved JSON. `AcceptedResolvedTestSpecV8.fromStore` first performs immutable readback of TestSpec v5, exploration attempt v3, successful trace v4, protected witness source, compiler attempt v3, and v8; the existing validators establish full linkage. The capability carries only TestSpec ID, start URL, and a frozen copy of the accepted v8 artifact into the runner. A forged prototype lacks its private runtime field and is rejected. The runner checks the approved profile fingerprint before opening a fresh protected browser session. V8 cannot enter the v7 or v6 entry points, and their artifacts cannot enter v8.

The runner consumes the compiled closed locator form, durable frame path, operation, and ordered source distinction. It receives no authored action text, never derives target role or name from prose, invokes M7/MCP, or repairs a locator. Authored actions use the v8 locator proved from requested intent and selected witness. Discovered prerequisites use their separately compiled target identity and execute in successful-path order; they cannot complete an authored step. During v8 replay, each durable frame anchor and each named semantic scope must remain unique before the final target is bound. This scope check is v8-specific and does not change historical v6/v7 replay behavior.

V8 verification goals use the existing reviewed deterministic v7 assertion evaluator for semantic count, unique property, and URL predicates. Complete zero matches are valid count evidence. A false evaluated predicate produces `QA_ASSERTION_FAILED` in the deterministic run. Missing, ambiguous, drifting, malformed, or unevaluable action/assertion targets produce non-QA binding, browser, or build failures. This package does not classify authoritative QA: two independently completed fresh replays and reproducibility agreement remain the production orchestration handoff.

The protected Add/Remove fixture demonstrates ordered link click, Add Element presence, Delete complete zero-count absence, Add Element click, and fresh Delete presence. Equivalent accepted source wording yields the same deterministic action behavior. Fixture mutations verify false count/property predicates, wrong role/name, target ambiguity, prerequisite drift, and frame/scope drift without linguistic fallback. V7/v6 runner compatibility remains separately tested.
