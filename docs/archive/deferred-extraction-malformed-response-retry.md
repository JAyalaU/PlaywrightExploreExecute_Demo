# Deferred extraction malformed-response retry

The active `deferred-action-v1` interpretation route now permits **one fresh retry in each extraction phase** when a completed provider response has no usable model JSON. The retry sends the same original source, reviewed prompt, and versioned response schema. It does not include the malformed response, a prior draft, browser state, or a repair instruction. The independent source-first phase remains separate and begins only after the primary phase yields a valid trusted extraction.

The retry decision is made before source validation or semantic admission. A completed malformed response envelope or invalid model JSON may retry once. A syntactically valid JSON object that fails the closed wire schema, exact source accounting, span/provenance, ActionGoal, VerificationGoal, graph, or admission checks stops at its original structural or semantic category without another model call. Refusal, incomplete provider response, authentication/configuration failure, transport failure, cancellation, deadline, ambiguity, unsupported material, and downstream failures also do not retry. The second malformed attempt remains a structural non-QA stop; no older-format fallback occurs.

The reviewed provider allowance remains 180,000 ms **per attempt**. The shared interpretation allowance is 780,000 ms: four possible full calls plus 60,000 ms reserved for local normalization, validation, and admission. Before retrying, the controller checks that the remaining shared allowance can still accommodate full subsequent provider calls. The gated deferred UI host deadline is 1,200,000 ms, leaving 420,000 ms after worst-case interpretation for browser, compiler, replay, cleanup, and persistence. Default and older-route host deadlines remain 300,000 ms. Protocol maxima increased only to accept the trusted deferred host selection; task/form/model data cannot select it. Test-only per-call/shared overrides remain bounded.

Restricted timing now optionally records at most four ordered attempt rows: phase, ordinal, elapsed and allowed milliseconds, remaining shared budget at start, whether the client settled before its boundary, a closed outcome, and a bounded provider response state (`completed`, `incomplete`, or `unavailable`). The status is `unavailable` when the transport has no trustworthy response state; it does not assert a late HTTP response was received. Older authenticated private accounting without attempt rows remains readable. Stop persistence authenticates the rows in `DeferredWorkflowPrivateAccountingV1`. After an accepted retry, a separate immutable HMAC-authenticated private attempt record is written before browser work, linked to the trusted source/admission digests and profile fingerprint. Fresh-process readback authenticates that record but grants no admission or replay authority. A persistence failure stops before browser mutation. No prompt, source, provider body, generated text, browser evidence, or exception string enters the attempt record or public ResultRecordV2/Python/UI projection.

Offline mocked validation: 79 interpretation/deadline/structural/retry/WP5A integration tests, 21 affected transport/protocol/adapter tests, and 17 Python host/deferred tests passed. Typecheck and build passed. Tests cover successful primary and independent retries, exhausted retry, malformed JSON versus valid-JSON structural failures, source and graph errors without retry, semantic disagreement, provider refusal/incomplete/HTTP failure, cancellation, full independent allowances after two near-limit primary attempts, authenticated restart and tamper rejection for a successful retry, private stop accounting, old-route outcome isolation, and public projection exclusion. No credentialed provider or public-target workflow ran. Actual provider latency and live malformed-response incidence require a separately authorized provider run.
