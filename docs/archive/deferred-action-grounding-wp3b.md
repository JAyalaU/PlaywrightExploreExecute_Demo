# Deferred Action Grounding WP3B: fresh compiler v4 / resolved v9

## Boundary and result

This package implements a separate deterministic compiler family for authenticated SuccessfulExplorationTrace v5. It follows WP3A's exact durable handoff and preserves the complete admitted source and endorsed mapping. There is no model call, English interpretation, legacy compiler fallback, v9 runner, production workflow selection, or provider/public-browser proof.

```text
actual TrustedSuccessfulTraceReadbackV5
 -> fresh protected same-profile/fingerprint session
 -> complete endorsed predicate, fresh owned labels/options, exact execution and effect
 -> CompilerAttempt v4 with protected fresh state chain and verified cleanup
 -> actual compiler-owned artifact
 -> separate immutable authenticated compiler-v4/resolved-v9 store
 -> TrustedResolvedTestReadbackV9 for a later model-free runner
```

The implementation is `app/domain/deferred-action-compiler.ts`, `app/exploration/deferred-trace-compiler-v4.ts`, and `app/evidence/deferred-compiler-store-v4.ts`. This new compiler module is deliberately separate from historical `trace-compiler-v4.ts`, which continues to implement trace v4 / compiler v3 / resolved v8.

## Fresh source and browser correspondence

The compiler requires an actual authenticated v5 readback capability. The original TestSpec v6/v2, source accounting, WP1 admission record and extraction versions/digests, exact authored obligations and target/argument/anchor ownership, full independent endorsement, successful witness, protected execution/post-effect, verification strategy, and historical retirement/state ordering are revalidated by the v5 store before this capability exists.

A narrow compiler-only factory on the existing grounding runtime retains that exact stored source and mapping. It never re-admits copied extractions, issues a WP1 semantic admission, or re-creates an M7 mapping capability. Its privately registered frozen mappings authorize only this fresh compiler runtime. The compiler source facade fails WP1/M7 origin checks and cannot be consumed by v5 exploration assembly. Observations use a separate private receiver-checked observation-owner handoff.

The fresh browser must have the same approved execution profile reference and effective fingerprint. The entire reviewed role family is queried across all current frames, with the existing 80-candidate / eight-frame completeness bounds. Exact authored role/name constraints and endorsed semantic-role/label realizations preserve their original ownership. A label narrows only through the reviewed native-label/ARIA-IDREF association. Native capability, a convenient discovered name, frame, or matching option never reduces an otherwise ambiguous control domain. In particular, a fresh additional native or custom eligible control, including one in another frame, rejects before mutation.

After complete goal uniqueness, fresh native-select enumeration must prove complete native ownership, an exact unique authored displayed label, enabled choice, single select, and unique executable value. The DOM value is freshly derived. If `Option 1` now maps uniquely to `fresh-value`, compilation may accept that new mapping; it never pins exploration's `runtime-1`. Missing/disabled/duplicate labels, executable-value collisions, or incomplete options stop without a resolved artifact.

The selected fresh frame must independently prove the same durable main/nested ancestry of exact title/test-id anchors. Historical owner digests and current refs remain correlation/provenance; they never become durable locators. The fresh predicate is renewed inside the existing protected exclusive action callback, and the exact reviewed operation and fresh admitted/runtime-derived argument execute on the retained node. The compiler requires the actual private successful witness and fresh post-effect. Fresh bindings are retired by the runtime's normal housekeeping; their newly issued continuity receipt is recorded explicitly. Historical retirement receipts are never executed as actions.

## CompilerAttempt v4

The closed attempt contains immutable source/trace/profile links, a fresh compiler session/attempt identity, bounded timestamps, typed checks, fresh successful action witnesses and retirement receipts, fresh trusted verification facts, fresh authored navigation state records, initial/final fresh state points, and a canonical attempt digest. Accepted attempts require profile and verified cleanup plus all required source/predicate/frame/execution/order checks for each action and source/verification/order checks for each verification. Every check belongs to the ordered source path.

The successful fresh proof chain is mechanically validated through preparation, final complete predicate, exact execution, post-effect, and explicit fresh retirement. Verification observation digests are reconstructed using the unchanged reviewed preimage; exact query/frame/result/evaluation and source strategy must agree. The whole fresh action/navigation/verification path follows one exact session/page/state/epoch chain. No undocumented state rebasing is allowed. Final proof validation failure demotes the compilation to a typed rejection instead of issuing an accepted artifact after a browser command happened to return.

`executionStops` holds only actual rejected, failed or `executed_unproven` invocation accounting in a rejected attempt. It is separate from successful fresh witnesses and must be empty for acceptance. There is no implicit retry, browser repair or stale-witness reuse. Compilation has a shared 120-second deadline; grounding retains its existing bounded exclusive leases and source/candidate bounds. Cleanup failure always rejects and marks cleanup unverified.

## ResolvedTestSpec v9 and deterministic vocabulary

V9 contains ordered authored navigation, deferred native action, and existing closed VerificationGoal assertion steps. It preserves compiler/trace/source/profile/admission provenance and a canonical resolved digest. Each action embeds the exact immutable source goal, total endorsed correspondence, broad reviewed candidate request/predicate, durable frame ancestry, operation, exact authored argument and compiler-derived executable argument. It carries a closed guard-v1 rather than any CSS/XPath/JS/model locator language.

The guard defines complete all-frame candidate evaluation before frame correspondence; 80 candidates/eight frames/80 native options; exactly one eligible target; proven native-label/ARIA-IDREF association where endorsed; native capability; exact owned authored option-label/value uniqueness; and a supported native effect. Native input/textarea fill requires exact entered value. Native-select choice requires exactly the compiler-mapped owned option to be selected. Checkbox/radio activation requires one trusted target-owned native click receipt plus the checked transition. V9 has no generic button/link activation, custom-control mechanism, arbitrary relationship, pending obligation, or retirement operation.

The replay argument policy is explicitly `require_fresh_mapping_equal_compiled_argument`. A future runner must freshly remap the authored option label and prove its owner/value uniqueness immediately before action. It must require the fresh mapping to equal v9's compiler-derived executable value; value drift is a non-QA stop, not dynamic repair. A bare role-only locator or `select_option(value)` without that guard is insufficient.

Existing typed VerificationGoal strategy projection is reused directly. Closed count, unique boolean/string property, and URL assertions keep their source strategy digest and exact query/comparison. An evaluated-false completed strategy retains its evaluated-false correspondence without becoming a QA verdict. Successful temporal strategies with no existing closed projection reject `UNSUPPORTED_VERIFICATION`; the compiler does not manufacture a new temporal runner language.

## Rejections, origin, and compatibility

All compiler stops are non-QA: profile/source mismatch, non-unique or missing target, label/option/frame correspondence failure, stale/incomplete evidence, unsupported representation/verification/activation, unproven effect, environment failure, or unverified cleanup. Rejection contains no v9 artifact. A replaced retained node that cannot be queried normally produces `INCOMPLETE_EVIDENCE` with actual `QUERY_UNEVALUABLE`, not an invented semantic conclusion. Changed options can produce `STALE_EVIDENCE`. Capability forgery and unauthenticated stored input are rejected before fresh browser authority is acquired.

The separate immutable `deferred-compiler-v4-resolved-v9` namespace uses its own persistent private HMAC authority key and owner-checked bounded regular files. Only actual compiler-owned capabilities may be written. Authenticated reads additionally require actual trusted v5 provenance, validate exact trace linkage and closed compiler/resolved integrity, and issue `TrustedResolvedTestReadbackV9` only for accepted results. Schema-valid JSON, recomputed digests, copied objects, callbacks, cross-authority copies and changed stored source/arguments cannot mint runner origin. The restricted host root/key remain the durable filesystem authority boundary, as in WP3A.

Historical trace/compiler/resolved families remain separately readable and unchanged. Additive domain/evidence exports do not select a workflow. The old observation verifier reexports the same pure domain witness reconstruction. V5 storage now loads assembler integrity helpers inside its already-async read/write methods, avoiding an ES-module initialization cycle from the new compiler handoff without changing admission/authentication semantics.

## Exact runner-v9 handoff

The future trusted host reads the authenticated compiler artifact using `DeferredCompilerV4Store.readResolvedV9(testSpecId, compilerAttemptId, actualV5Readback)` and passes only the resulting actual `TrustedResolvedTestReadbackV9`. The runner obtains its checked source trace, compiler attempt and v9 via `requireTrustedResolvedTestReadbackV9`; a parsed v9 object alone is insufficient.

The future runner must open a new approved same-profile/fingerprint protected context and follow authored start/navigation/action/verification order. For every action it must independently reconstruct guard-v1 from the complete endorsed correspondence, query all eligible frames before durable frame matching, renew complete labels/options and uniqueness under protected exclusive execution, verify native capability and exact argument/value policy, execute exactly once on the retained current node, and require fresh supported post-effect. It must preserve explicit state continuity and typed non-QA guard/environment/cleanup stops. No old refs, exploratory values, historical receipts, discovery retry, model/MCP repair, generic activation or unsupported relationship may be used as executable authority. No runner implementation is included here.
