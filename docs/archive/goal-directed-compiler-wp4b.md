# Fresh goal-directed compiler (WP4B)

`compileSuccessfulTraceV3` is a private deterministic consumer of an accepted, immutable SuccessfulExplorationTrace v3. It reads the v3 artifact and protected observation capture through storage validation, opens a separate protected browser with the job's effective profile, reconstructs the ordered action path, and re-observes each verification strategy using the closed WP2 read-only API. It uses no model decisions, old MCP references, old frame IDs, or exploration values as fresh browser facts. It does not run QA or dispatch ResolvedTestSpec v7 to a runner.

For an action, the compiler reconstructs a closed role/name locator from the reviewed action binding, re-establishes durable frame anchors, measures uniqueness, checks the authored identity and selected target, executes the action, and checks its observed effect. A link with a recorded destination must reach that destination. Existing targeted-action candidate digests are recomputed for v7 contract validation. The narrowly extended authored identity form permits an exact `Add/Remove Elements link` label containing punctuation; it requires literal role/name equality with the protected binding and fresh locator.

For a verification goal, `assertionFromStrategyV1` projects the reviewed comparison into the WP4A algebra. The compiler recreates the same closed semantic query, property read, or URL read in the fresh browser. WP2 returns a complete count, including zero without any selected element reference; it returns a typed error for invalid scope, ambiguous unique property, browser error, and other unevaluable reads. The compiler compares the **fresh predicate result** with the source strategy's evaluated boolean. It never rewrites the authored predicate from a fresh value. Thus a source false predicate can compile when fresh evaluation is also false; a source `Delete count == 0` that becomes false in the fresh context stops with `POSTCONDITION_MISMATCH`, without a QA verdict. Presence remains a match-count condition when the fresh target is hidden.

Temporal strategies have no faithful v7 replay representation and produce a persisted compiler-attempt v2 rejection with `UNSUPPORTED_TEMPORAL_REPLAY` and runtime category `compilation_unsupported`. Reconstruction, identity, property uniqueness, scope/frame, profile, or observation failures after session creation use `compilation_stop` with a distinct typed reason. Neither outcome creates v7. If the protected context cannot open, compilation raises a non-QA environment error and writes no compiler-attempt v2 artifact: the contract's `freshSessionId` must identify an actual session. Accepted compiler v2 and resolved v7 are atomically written together under `agentic-compiler-attempts-v2`; rejected compiler v2 attempts are immutable standalone records. Both have deterministic readback against the v3 source, protected capture, TestSpec, profile, and WP4A validators. The released compiler v1/v6 namespace and runner dispatch are untouched.

The remaining work is a dedicated v7 deterministic runner: it must execute only accepted v7 assertions in two separate fresh protected replays and classify QA only from those run results. Production orchestration must also connect v3 capture and this compiler path before a public agentic-v2 workflow can use goal-directed verification. Environment-level validation with a live protected browser service and approved public target remains a release gate, not an assertion in this compiler.
