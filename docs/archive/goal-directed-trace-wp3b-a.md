# SuccessfulExplorationTrace v3 contract (WP3B-A)

This package defines and validates a private trace v3 object. It does not assemble or persist one. Production still writes v2, and v1/v2 parsers remain separate and unchanged. No compiler, resolved artifact, runner, public result, or QA authority consumes v3.

## Ordered path

`SuccessfulExplorationTraceV3Schema` keeps the v2 source, attempt, profile, session, state-chain, binding, and time envelope. Its `successfulPath` is one bounded sequence containing existing v2 action/wait/structured-assertion records and a new `verification_goal` record. Every authored TestSpec v4 step appears exactly once in source order; a discovered prerequisite can appear only before the authored step it enables. Sequence numbers are contiguous, state digests link every entry, and a verification entry is read-only (`preStateDigest === postStateDigest`). `completedOriginStepIds` repeats the exact authored order. No implicit upgrade of a v2 artifact occurs.

The verification record carries the source goal step ID and digest, WP3A successful-strategy digest, action ordinal, ordered observation IDs and full closed `TrustedObservationResultV1` facts, the bounded `VerificationComparisonV1`, evaluated boolean, and `satisfied` or `unsatisfied` conclusion. These are exploration observations, not replay assertions or QA pass/fail results. The schema has no fields for model reasoning, provider output, failed queries, abandoned strategies, recovery branches, arbitrary selectors, or executable expressions. `unresolved` and `unsupported` cannot be serialized as successful verification entries.

## Protected validation boundary

`parseSuccessfulExplorationTraceV3` requires a `ProtectedTraceObservationSourceV3` supplied by the future protected assembler. It must look up exact runtime-owned WP2 observation records and the exact successful WP3A journal record. The trace cannot validate its own trusted provenance merely by presenting plausible IDs or digests. The parser compares each copied observation byte-for-byte by parsed field structure with the protected source, including query, typed result, frame, attempt/session/page/profile, state and mutation epochs, time, and witness digest. It also checks the source journal digest, ordered operands, comparison and conclusion. A missing source or record fails closed. No model-supplied fact may implement this source.

The source supplies each observation's capture path position, separately attested action-path state digest, and WP3A action ordinal, plus protected attestations that it was current at capture and that the final operand was current when the goal completed. The path position is the number of successful records already completed; the parser checks the protected path-state digest against that exact position. WP2's `observation.stateDigest` hashes a different page-state representation and is checked against the exact runtime-owned WP2 record, not equated with the action-path digest. It does not equate WP3A's action ordinal with every changed path record, because navigation and passive transitions may also change state. A non-temporal verification requires its operand in the goal's current state. Snapshots, query errors, incomplete results, mismatched owners, and forged facts are invalid. Query frame and scope must match the trusted frame proof and authored subject hints; unresolved frame ownership cannot prove a target query. Without subject hints, role and name must still be justified by the authored clause. Scoped queries require exact authored scope count, order, kind, and name or row-cell value; nested frame anchors must likewise match exact authored frame hints. Extra query narrowing is rejected because it can create a misleading zero-match result. Prose scope hints that cannot be mapped exactly to reviewed query values fail closed. The parser recomputes the typed comparison from the trusted values; even a journal and trace that agree on a false claim are rejected.

For a temporal `appears` or `disappears` comparison, the first observation may be historical only with a matching query, same session/page, earlier state/mutation epoch and timestamp, and a later current observation. The record lists all changed-state path record IDs between their capture path positions, in order. At least one such transition is mandatory, and WP3A's authenticated action ordinal must advance as its temporal strategy requires. A final absent count by itself cannot establish disappearance. Historical evidence is not allowed for ordinary final-state comparisons.

The WP2 observation witness hashes the runtime construction payload before its schema parse. The v3 parser therefore uses exact protected-source record equality and witness correlation; it does not invent a new hash preimage by serializing a parsed record in a different field order.

## Assembly and persistence handoff

WP3B-B supplies this assembly and persistence bridge. It captures runtime-owned WP2 records at their actual path positions, validates the complete action and strategy journals, and stores the accepted trace with a restricted protected-source bundle in a separate immutable v3 namespace. Readback rechecks the bundle, witness hashes, ownership, source/profile links, and this parser. A persisted trace cannot be treated as runtime-authenticated by schema validation alone.
