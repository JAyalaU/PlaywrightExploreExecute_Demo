# P4-G1 decision: restricted live browser images

Status: **complete for P4-2 implementation**. This is a reviewed decision contract, not an implemented feature. It closes P4-G1 in the [Phase 4 plan](phase-4-implementation-plan.md). P4-1 is complete under [its release proof](p4-1-live-proof.md).

## Boundary and authority

Live images use a separate `liveImageVersion: "1"` exchange. They are **ephemeral restricted observability data**, neither persisted evidence nor a report projection. They never enter TestSpec, ResolvedTestSpec, the artifact store, ordinary evidence, subprocess-v1 stdout/stderr, `eventStreamVersion: "1"` frames, or `reportProjectionVersion: "1"`. Existing final/failure evidence capture and its `sensitiveBinaryApproved` gate remain separate; that flag alone never permits live image display. Conversely, live-image approval never authorizes stored evidence reads.

The local operator must explicitly approve **both** `captureApproved` and `displayApproved` in a closed, trusted `liveImagePolicyVersion: "1"` configuration section loaded by Node. Both default to false when the section is absent, preserving legacy trusted configurations and profile fingerprints. Python/Streamlit form fields, task text, model output, and page content cannot set or elevate either permission. Node checks both permissions before acquiring or sending pixels; the Python host accepts bytes only from the authenticated Node child for that run. The local, loopback-only, single-operator UI is the approved display audience. Captured pixels may contain secrets; there is no claim of reliable pixel redaction. Operators must use a page suitable for local viewing and close the UI/browser tab after use. This does not protect against malicious software running under the same local operator identity.

Node alone captures from a page in the **current** `ProtectedBrowserSession` owned by the M6 attempt or deterministic replay run. `observationOwner` already distinguishes `attempt` and `run`; capture may attach to that lifecycle without giving Python a browser handle. For M6, capture only the active main page of that protected context. For replay, capture only the page created for that run. No page is selected by URL, task text, MCP response, frame request, or Python. If no page exists, the page is closed, or multiple candidate main pages make ownership ambiguous, do not capture. Navigation, redirects, and page closure are normal reasons to skip a frame. Capturing may neither execute page script nor trigger navigation, select a locator, modify steps, or add an observation action to deterministic replay.

## Capture schedule and limits

Use a Node-owned timer while an eligible protected session is active. Attempt at most one screenshot every **3 seconds**, with no overlapping capture, at most **32 accepted frames** and **120 seconds** of capture opportunity for one workflow across exploration and both replays. The counter and deadline do not reset when a protected session changes. Each capture has a **1-second** deadline; a timed-out, closed, ambiguous, or oversized capture is discarded. Three consecutive capture failures disable further attempts for that workflow. Capture work is best-effort and must never be awaited by M7, MCP tool selection, locator acceptance, or the deterministic runner's step execution. If measured capture overhead or a stuck capture cannot be isolated from execution deadlines, P4-2A must stop and report the risk rather than changing runner semantics.

The transmitted image is a viewport-only JPEG thumbnail, at most **800 × 600 pixels** and **128 KiB**. Trusted Node may scale and encode the active page's screenshot; it must check dimensions, format, and byte length before transmission and discard anything over limit. No full-page capture, trace, video, arbitrary crop request, raw screenshot buffer forwarding, alternate page, or archive is in this contract. The in-memory producer queue holds **one** pending image; a slow receiver causes image drops rather than backpressure on engine work. Total accepted image bytes are at most **4 MiB** per workflow. Existing protected Chromium control and proxy-only egress remain unchanged; no browser endpoint or new browser networking is introduced.

## Private delivery and correlation

The trusted Python host creates a second per-run IPv4 `127.0.0.1` listener before launching the Node child. It generates a fresh random 256-bit **image-only, single-use capability**, separate from P4-1's event capability, and passes the endpoint, capability, and P4-1 `streamId` to Node only through trusted launch environment. These values never enter the request JSON, Streamlit state, browser container environment, command-line arguments, evidence, or general diagnostics. Node connects once, authenticates with `liveImageVersion`, `streamId`, and the capability; Python verifies them, accepts one connection, and closes the listener. Failed authentication or an externally bound listener fails closed before pixels are sent. A disabled policy sends only a closed `capture_disabled` state and no bytes. An enabled image channel must authenticate before engine work; a later disconnect degrades image observation without altering the Node-owned QA result. Subprocess-v1 stdout remains one final JSON result.

The image exchange is length-framed: a closed, bounded UTF-8 JSON header followed by exactly its declared JPEG byte count for an authorized frame. A frame header contains only `liveImageVersion`, `streamId`, monotonic `frameSequence` (1–32), `sourceEventSequence` (the most recent *emitted* P4-1 event at capture start), `testSpecId`, profile reference and fingerprint, `owner` (`attempt` or `run` plus its generated ID), UTC capture time, JPEG MIME type, width, height, and byte count. It contains no URL, page text, locator, artifact path, hash, provider data, or arbitrary map. Closed state messages carry no image bytes and use only `capture_disabled`, `not_captured`, `temporarily_unavailable`, `limit_reached`, or `closed`. Each header is at most **2 KiB**; Python rejects duplicate keys, unknown fields, wrong version/stream/profile/owner, nonmonotonic frame sequence, impossible event sequence, invalid JPEG/dimensions/length, oversized bytes, and any frame after closure. Rejection withholds that image stream and leaves final QA untouched. If an enabled channel cannot authenticate before engine work, the bridge fails closed before starting that work; a channel lost after work begins only makes images unavailable.

The P4-1 `(streamId, sequence)` key and validated attempt/run/profile IDs align a frame with the live timeline; they **never authorize** image access. Python displays a frame only if the independently validated P4-1 stream has established the same profile and owner and reached `sourceEventSequence`. A truncated but otherwise valid event stream may show only frames whose correlation is still established; an unavailable or inconsistent timeline withholds images rather than guessing ownership. No new P4-1 event kind or field is required. Later P4-3 may reuse the correlation identifiers for viewer labels, but cannot reuse this image capability as viewer authority.

## UI, lifetime, and failure semantics

Python validates and keeps at most the **latest two** authorized frames in memory, replacing older bytes. Streamlit refreshes with its existing local run fragment and shows the latest authorized thumbnail labeled with its attempt/run and capture time. The UI explicitly distinguishes `capture_disabled`, `not_captured` (authorized but no valid frame yet), `temporarily_unavailable`, `limit_reached`, and an available frame. It does not show a blank image as evidence of browser failure. During session transitions it may retain the last validated frame with its original owner label until replaced or expired, never relabel it as belonging to the next session.

Node stops capture and closes its image sender when the workflow ends, on timeout/cancellation, on page or session disposal, or when authorization is revoked by process shutdown. Python closes the listener/socket with the supervised child, clears retained frame bytes no later than **60 seconds after the run ends**, and does not write frames to disk or expose a path-based read API. Streamlit drops its frame reference at expiry. Pixels already delivered to the local browser may remain in browser memory/cache until that tab closes; P4-2 does **not** claim remote erasure or immediate browser-cache purge. Implementation must verify that its chosen Streamlit rendering path creates no externally reachable or reusable post-expiry image endpoint; otherwise P4-2B is blocked for security review. Viewer disconnect leaves the already bounded engine run subject to its normal deadline, as in P4-1; it does not silently cancel or change QA. Forced child termination retains the existing `cleanup: unverified` semantics and must clear host-held bytes and inspect residual browser containers when feasible.

Image capture/transport errors are observation failures. They cannot reclassify QA, weaken locator quality, alter network policy, or make an intervened/observational run autonomous. Existing stored final/failure screenshot availability remains independently represented by report projection v1. If the image policy is absent, disabled, or cannot be validated, there is no capture and no image byte exchange. No image is reconstructed from restricted stored artifacts as a fallback.

## Implementation and validation handoff

- **P4-2A — evidence/backend developer with Node/browser owner:** add the closed trusted image policy and Node-only capture coordinator at protected-session lifecycle seams. Keep image counters/deadline across M6 and both replay sessions; prove normal capture, disabled mode, ambiguity/closed-page skips, navigation and timeout degradation, no runner timing dependency, and cleanup. Do not modify stored evidence or replay outputs to carry live bytes.
- **P4-2B — Python host integrator with security reviewer:** add the separate authenticated image channel, compatible closed producer/consumer validators, bounded in-memory buffer, and local Streamlit display. Prove wrong capability/stream/profile/owner/event sequence, stale frame, malformed JPEG, oversized frame, unavailable event stream, expiry, and post-close access denial. Verify bytes never enter subprocess-v1 or projection-v1 responses and no arbitrary artifact/path access is possible.
- **P4-2C — test automator and human operator:** run credential-free protected-browser normal, disabled, slow-consumer, capture-failure, cancellation, and cleanup cases; compare final QA/replay semantics with capture off. Then run a separate human-operated real-provider UI proof on an approved non-secret page, recording only image state/count/bounds/correlation, typed result, and cleanup. A skipped Docker test or mock does not close the live gate.

The principal implementation risk is that screenshot acquisition or Streamlit media retention may violate the bounded observation promise. Validate one normal protected workflow, one failed/disabled capture, and the Python/Streamlit integration edge before manual proof. If those bounds cannot be enforced, keep P4-2 blocked rather than broadening evidence access or weakening the existing browser and replay boundaries.
