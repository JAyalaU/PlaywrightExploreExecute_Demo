# Agentic exploration domain contracts (WP1)

This is the contract slice of the reviewed exploration/compilation redesign. The legacy M6/M7 handoff remains available for `ResolvedTestSpec` versions 2–5. The agentic execution path is selected explicitly by the trusted local host as `agentic-exploration-v1`; it uses subprocess protocol v2 and report projection v2. WP2A supplies current-state action facts; WP2B assembles and stores successful v2 traces; WP2C supplies bounded agentic exploration. WP3 compiles the private trace in a fresh context; WP4A runs the accepted v6 artifact deterministically; WP4B composes two fresh replays. The contracts do not grant access to private traces, branches, or compiler details through either external protocol, report projection, live events, or Streamlit.

## Boundary and versions

| Contract | Version | Purpose |
|---|---:|---|
| `ExplorationTargetBinding` | `bindingVersion: "1"` | Bind one selected MCP ref to the current protected session, page, frame, snapshot epoch/digest, source goal, and closed operation. |
| `ExplorationAttempt` | `attemptVersion: "3"` | Correlate a path-established attempt with exactly one `successfulTraceId`, or record a closed automation/environment/cancellation reason. Legacy stored attempt version 2 is unchanged. |
| `SuccessfulExplorationTrace` | `traceVersion: "1"` | Preserve the ordered successful path only, with action, navigation, wait, and assertion observations. |
| `SuccessfulExplorationTrace` | `traceVersion: "2"` | New agentic runs preserve protected cross-context frame ownership and witnessed deterministic passive-transition conditions. Historical v1 remains readable. |
| `SuccessfulExplorationTrace` | `traceVersion: "3"` | Private goal-directed contract for one ordered action/verification path with exact protected observation and strategy correlation. No production assembly or persistence yet. |
| `ExplorationBranchDiagnostic` | `diagnosticVersion: "1"` | Preserve bounded failed/recovery branch codes privately, separate from replay steps. |
| `CompilerAttempt` | `compilerVersion: "1"` | Link one trace to independently checked closed-form, durability, uniqueness, selected-target, profile, and postcondition facts. Multiple immutable attempts may reference one trace. |
| `ResolvedTestSpec` | `schemaVersion: "6"` | Link an accepted compiler attempt and successful trace to an ordered compiled path with exact profile fingerprint and closed locator forms. |

All records use immutable identifier-shaped IDs, the source `testSpecId`, `explorationAttemptId`, exact execution profile ID/version, and effective profile fingerprint. `assertImmutableAgenticArtifact` rejects changed content under the same artifact ID. The production store must use the same immutable-write rule when persistence is wired. A trusted profile/catalog remains authoritative for the fingerprint; form input cannot supply its own approval.

## Trace v2 contract gate

`SuccessfulExplorationTraceV2` is a separate closed schema and parser. Historical v1 traces remain readable and immutable; parsing never rewrites or upgrades them. The v2 parser preserves v1 source, attempt, profile, session, authored-goal, state-chain, binding-use, and successful-branch validation, then checks the additional provenance below. An explicit `unproven` frame owner is a valid honest observation but **cannot authorize compilation**. Ambiguous anchors cannot be represented as a `nested` owner with a guessed choice. The compiler must reject `unproven` until a later protected observation establishes a new, immutable trace.

Every v2 successful-path target binding carries `frameOwnership`, separate from its original session-local `frameId`. `main` binds a protected main-document attestation digest to the selected full snapshot. `nested` carries a bounded root-to-leaf chain (at most eight) of iframe anchors. Each anchor has one exact `title` or reviewed `testId` identity, the digest of the owner-frame snapshot where that anchor was observed, and a protected unique-match count of one. The compiler must re-establish each anchor in order in its fresh protected context and verify the candidate target in the resulting frame. An opaque runtime frame ID, DOM position, arbitrary selector, or URL/effect match cannot stand in for this proof. If an anchor is ambiguous, unsupported, or not attested, WP2 records `unproven` with a closed reason; the validator rejects malformed/ambiguous `nested` paths and extra identity fields.

A v2 `state_observed` record is a `reach_state` discovered prerequisite with a changed pre/post digest and a **closed, satisfied wait condition**. It uses the existing `WaitConditionSchema`: exact URL, reviewed URL pattern, target visible, or target value. It also records a timeout-policy reference and a protected `protected_condition_check` witness. The witness binds the trace record ID, timeout-policy reference, exact condition digest, the record's observation digest and post-state digest, and an observation time inside the source attempt. A targeted condition requires a distinct current-state `wait_for` binding owned by the same attempt/session/profile and source goal, issued before the observation. An untargeted URL condition cannot carry a binding. A record with only digests, an unsatisfied condition, mismatched witness, unaccounted binding, or broken goal/state chain fails v2 finalization. The timeout policy is a closed reference; its actual duration must still be resolved by the trusted runtime at capture and compilation.

The v2 schema validates the shape and correlation of protected facts. It does **not** make model-authored claims authoritative. WP2A now captures a `TraceBindingV2` privately at `bind()` while leaving its v1 action binding unchanged. The main owner is attested by the full selected snapshot. For nested frames, WP2A walks actual Playwright parent frames root-to-leaf; each iframe is matched against its siblings by a unique exact `title` or `data-testid`, and the protected parent-frame snapshot is hashed. Ambiguous, unsupported, or unattested anchors produce `unproven`; opaque frame IDs are never promoted to cross-context identity. A nested capture rechecks the full MCP snapshot before accepting the attestation. `traceBinding()` retrieves the immutable captured fact for future assembly; it cannot authorize an action.

WP2A also exposes `capturePassiveTransition()` for the **current** protected observation. It derives the condition from the validated authored `assert_url` or `wait_for` step, or from the explicitly identified next `click`/`assert_visible` target as a visible readiness prerequisite. The latter requires an exact authored role/name agreement, scope agreement, a current owned `wait_for` binding, and absence of that same role/name in the prior full snapshot. URL/target satisfaction is checked against the protected page at capture time; the timeout policy is resolved from the effective profile and the witness hashes the exact closed condition, record ID, current observation, and post-state. A prior observation and the current observation must share a mutation epoch, so a WP2A action cannot be misclassified as passive. A stale, ungrounded, unsupported, or unsatisfied transition has no v2 witness. The API does not take a model-authored condition or frame claim. M7 invokes protected capture before the next action or assertion whenever the observed state differs from the assembled path. It persists the witnessed condition in v2; it never invents a condition after the action.

WP2B finalizes new agentic runs only as complete v2 successful paths with captured facts, rejects required `unproven` target-frame ownership, and keeps abandoned/recovery branches private. A state gap without a grounded, satisfied predicate produces a typed unsupported automation stop and no successful trace. WP3 independently re-establishes frame and target correspondence and verifies the recorded passive predicate in a fresh protected context; a satisfied final URL alone is insufficient. The separate WP4A deterministic runner entry point consumes validated v6 with that provenance. The explicitly selected agentic-v2 production workflow uses this path; its live release proof is recorded in [agentic-v2-release-gate.md](agentic-v2-release-gate.md).

## Current-state binding

`parseCurrentTargetBinding` compares the binding with the **active** protected session context immediately before an action: attempt/profile/fingerprint, session, page, frame, snapshot epoch and digest, selected ref, and selected-node semantics must all agree. The active context attests that the ref appears exactly once; click/fill/select also require visible and enabled state. The binding carries `issuedAt`; the protected session enforces a short freshness window before acting. WP2 constructs this active context from the protected MCP snapshot and browser state, never from model or page-supplied claims. The binding is ephemeral authority only. It is not a replay locator and cannot enter the deterministic runner.

The binding operation is closed to target actions, targeted waits, and targeted assertions. Unsupported actions, stale refs, wrong operations, wrong owners, and mismatched selected-node facts fail validation. Navigation and untargeted URL assertions do not use a target binding. A role/name or scoped locator is **not required** to make a currently unambiguous bound MCP ref actionable during exploration.

## Successful path and branch isolation

The trace stores one ordered `successfulPath`, an exact authored-goal sequence, pre/post state digests, observation digests, targeted binding IDs, and closed operation data. It may include discovered prerequisites before the relevant authored operation; each carries a closed `prerequisiteReasonCode` of `expose_target` or `reach_state`, which later v6 compilation must preserve exactly. An assertion observation can be `passed` or `failed`; exploration can establish an evaluable path even when the observed assertion is false. Replay alone classifies the application QA outcome.

When the protected page changes between authored operations without an agent action, the controller asks WP2A to capture a closed `state_observed` condition and satisfied protected witness before the next operation. Digests remain provenance, not replay authority. Incidental DOM drift with no grounded condition stops without a successful v2 trace. Fresh-session recovery still stops if such a passive transition is in its prefix and cannot be reconstructed safely.

Validation requires every authored step exactly once and in order, contiguous state digests, exactly one action record sequence, exact source operation/literals, and a current-attempt binding for each targeted record. A binding not used by the successful path is rejected. Failed candidate and recovery branches instead use a separate closed diagnostic record. Its allowlist contains codes, IDs, and snapshot digests, without raw page text, URLs, provider output, MCP payloads, locator expressions, or model reasoning. These private records do not become replay steps or UI/live-event payloads.

WP2B `SuccessfulTraceAssembler` accepts action records only from the complete WP2A journal. At finalization it rereads that journal from the supplied WP2A accessor; a caller-provided subset cannot hide a performed mutation. The future M7 controller supplies observed navigation, wait, and assertion records; the assembler enforces contiguous state ordering, source goal order, binding ownership, and complete mutation accounting before finalization. It records `observedEffect` from protected pre/post state digests. `attachEvidence` may add at most eight private attempt-owned evidence references per successful-path record; the store verifies descriptor owner and source-step correlation. An observed false assertion may complete a trace and carries no QA verdict.

WP2C uses `runAgenticExplorationV1` only when the caller explicitly selects `workflowVersion: "agentic-exploration-v1"`. Its private M7 decision contract is `decisionVersion: "3"` with closed `inspect`, `act`, `observe_target`, `evaluate`, and `stop` decisions. It never changes the legacy M7 v2 decision contract or the existing handoff. A model-selected ref must occur in the bounded snapshot; WP2A independently binds and rechecks the full current snapshot, session, page/frame, node, operation, visibility, enabled state, and authored contradiction before an action. Neither `browser_generate_locator` nor the locator-quality gate authorizes exploration. A click/fill/select is followed by protected observation and an explicit M7 evaluation; action completion by itself does not complete an authored goal. URL and link-collection assertions are evaluated from the protected page, and present targeted predicates use a read-only current-state binding. An evaluable false predicate is recorded as such, without a QA verdict.

WP2C enforces hard caps of 60 model decisions, 40 state-changing actions, 80 full snapshots, two candidate actions per authored subgoal, two changed-state recovery branches, six discovered prerequisites per authored step, and 120 seconds total exploration. The production WP2A adapter counts every full MCP snapshot, including internal pre-action rechecks and post-action observations. Per-call model timeout, output size, and MCP limits remain bounded. A failed current-state binding returns to observation. Repeating a failed candidate without new protected evidence stops. A verified unchanged-state candidate may be explicitly moved from the WP2A successful journal into a private failed-branch transition; the abandoned fact remains in memory and is never silently discarded. Changed state never permits an in-place retry: the controller opens a fresh protected context and reconstructs the known successful prefix using unique snapshot semantics, approved operations, and matching normalized post-observation and URL. Unverifiable reconstruction stops. Browser Back and arbitrary rollback are not used. Failed choices are written as restricted branch diagnostics before a successful trace is persisted; a prior-session branch requires a `recoveredToRecordId` in the final trace. This correlation permits honest fresh-session recovery without claiming that the old session is the final trace session.

`LocalArtifactStore` atomically creates one immutable `agentic-explorations/<attemptId>.json` containing the linked v3 attempt and successful trace. New `agentic-exploration-v1` runs write v2; historical v1 readback is preserved without upgrades. Closed failed/recovery facts are separate private `developer-diagnostics/<attemptId>/branch-<ordinal>.json` records; finalization rejects mismatched branch session or recovery linkage, then closes branch writes for that attempt. Compiler attempts each get an immutable `agentic-compiler-attempts/<traceId>/<compilerAttemptId>.json`; several can reference the same trace. An accepted attempt and v6 artifact are stored together in that file. These paths are internal store implementation details, not artifact references for report projection or Streamlit. The legacy attempt/resolved store and runner remain unchanged.

## Compiler and v6 executable boundary

An accepted compiler attempt must contain passing profile and ordered-postcondition checks, plus closed-form, durable-identity, unique-match, and selected-target checks for each targeted successful-path record. Target checks carry a SHA-256 digest of the exact declarative locator form they verified. `parseResolvedTestSpecV6` rechecks this digest against every persisted target locator, the complete trace ordering, source literals, profile/fingerprint, and the accepted compiler attempt's `resolvedSpecId`. A rejected compiler attempt cannot authorize v6.

`compileSuccessfulTraceV1` retains its historical exported name and reads either immutable v1 or v2 traces from the private store. It opens a new protected MCP/browser context under the same effective profile and fingerprint, reconstructs only the successful path, and atomically persists an accepted attempt with v6. A targeted v1 trace still stops: its opaque frame IDs cannot prove cross-context ownership. For v2, an attested main frame binds to the fresh main document; a nested owner is reconstructed root-to-leaf by unique exact `title` or reviewed `testId` iframe anchors. An ambiguous, absent, or `unproven` anchor rejects compilation. The v6-only compiled locator carries the verified `framePath`; the candidate digest and v6 validator bind that path to the original trace. The legacy runner and locator AST are unchanged. Within the proven frame, WP3 verifies exact closed role/name or reviewed row scope, unique match, observed semantic identity, and destination when present. WP1 quality witnessing, legacy M7 explicit-identity checks, and WP3 compilation share one closed authored role/name parser. It accepts the reviewed quoted forms and bounded explicit unquoted role-first text/name/label forms (for example, `link that says Status Codes` and `link with text 200`), plus the existing exact name-before-role form with its matching `go here` sentence context. Ambiguous or unmatched prose supplies no identity witness; the parsed role and name must exactly match the selected-node facts, and WP3 must still independently prove one fresh match, target correspondence, and required scope/frame constraints. Fresh MCP refs witness main-frame correspondence only; exploration MCP refs are never reused as compiler selectors. Compiler verification is not an authoritative QA replay. Rejected attempts have immutable records, and multiple attempts may reference one trace.

In v1, `state_observed` remains a necessary provenance record but carries only state digests, without a closed deterministic wait predicate. WP3 rejects any v1 trace containing such a record with `UNSUPPORTED_CAPABILITY` and persists no v6. The historical real WP2 Status Codes proof contains one such record and remains **non-compilable**. For v2, WP3 uses the exact captured closed condition and timeout policy in its original successful-path position. It waits for the predicate in the fresh protected context, then verifies unique target/frame correspondence before persisting the ordered v6 `wait_for` step. Protected witness linkage is revalidated; digests alone never become wait conditions. A fresh v2 Status Codes-shaped fixture compiles its witnessed `target_visible` readiness before the `200` click without a site-specific rule.

The historical v1 Status Codes artifact remains non-compilable because it lacks v2 frame and passive-condition provenance; it is never rewritten. New v2 traces supply the protected facts required by WP3. Focused fresh-context compiler regressions cover main-frame actions, exact-cell row scope, witnessed passive readiness, nested-frame correspondence, duplicate targets, semantic drift, stale exploration refs, and immutable repeated attempts. WP4A added the v6-only deterministic locator binder for `framePath`, and WP4B composes the production handoff and two fresh authoritative replays; WP3 itself does not classify QA.

The v6 locator stores the closed declarative `validatedForm`, an optional verified v6-only root-to-leaf `framePath`, typed observed identity and accepted quality, and optional raw MCP expression as private provenance. It cannot be an arbitrary selector or model-generated Playwright code. The existing page-locator AST is reused; the frame path cannot be combined with a legacy single-frame locator. A v6 artifact is parsed through the separate `parseResolvedTestSpecV6` function with the source TestSpec, attempt, trace, and compiler record supplied. `executeResolvedTestSpecV6` validates that full linkage and the current approved profile fingerprint before browser launch, then binds each frame anchor uniquely in order and executes the compiled steps and waits without MCP or model calls. A v6 binding failure, including an absent assertion target, is a reproducibility/binding failure; an evaluated false assertion remains a QA failure. The legacy `executeResolvedTestSpec` still rejects v6. The agentic production handoff and two fresh authoritative replays have passed the release gate documented in [agentic-v2-release-gate.md](agentic-v2-release-gate.md).

## Typed outcomes and compatibility

`AgenticOutcomeV1` separates exploration path established/unresolved/unsupported, compilation accepted/durability failure/unsupported, replay reproduced/not reproduced/execution failure, QA assertion pass/fail, environment unavailable/policy denied/cancelled, and cleanup verified/unverified. It is a private domain vocabulary, not a silent extension of the legacy `ResultRecord`, subprocess-v1 terminal result, or report projection. The reviewed external mapping is [agentic-external-outcome-mapping.md](agentic-external-outcome-mapping.md): agentic jobs use the separate, explicitly versioned v2 terminal/wire/projection contracts; legacy v1 remains available for compatibility.

## WP4B production composition and release status

`runAgenticProductionV1` accepts only an explicitly selected `workflowVersion: "agentic-exploration-v1"` and an already persisted, immutable TestSpec. It invokes the bounded WP2 controller, compiles a successful v2 trace in a fresh protected verification context, reloads the accepted compiler/v6 linkage, then executes and stores the exact v6 artifact twice in separate fresh browser sessions. Each v6 run is correlated to the accepted compiler attempt before persistence; the existing evidence capture policy and protected browser factory apply. A private exploration or compilation stop returns without a QA verdict. Binding/wait/browser failure remains a replay automation stop. Distinct replay status/reason sequences or terminal categories produce a reproducibility stop. Only matching completed deterministic assertions yield a private QA pass/fail result. The headed path remains observational under the local host's existing provenance rules.

The trusted local host selects the workflow once before launch. Agentic jobs use the reviewed v2 terminal, subprocess, and report-projection contracts; legacy jobs continue to use the v1 family. The operator-reported Status Codes release proof verifies the integrated agentic path and two authoritative replays. Agentic P4 terminal timeline correlation remains deferred and unavailable; no legacy timeline is used as terminal authority.

Versions 2–5 remain readable under their existing schemas and validators. No existing stored record is rewritten. The current runner, evidence store, subprocess protocol v1, report projection v1, P4 live event stream, and UI are unchanged in WP1. The migration must not let a v6 object reach the legacy runner before compiler and fresh replay integration is complete.
