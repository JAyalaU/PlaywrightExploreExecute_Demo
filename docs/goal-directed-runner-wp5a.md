# Deterministic ResolvedTestSpec v7 execution (WP5A)

`executeResolvedTestSpecV7` is a private runner entry point. It validates TestSpec v4, the accepted compiler-attempt v2, SuccessfulExplorationTrace v3, the protected observation source, and ResolvedTestSpec v7 before opening a fresh protected browser session. The approved profile fingerprint must match. The released v6 entry point still validates only v6; there is no cross-version fallback, LLM, or MCP below v7.

The runner replays the accepted ordered actions and verification goals. Actions retain the existing compiled action implementation. For a verification goal, fixed runner code reconstructs the v7 semantic query from durable main/nested frame anchors, unique within-scopes, role, and exact accessible name. Queries include hidden targets, matching WP2 existence semantics. A complete count of zero is an evaluated result. A unique property read requires exactly one match; multi-match and no-match property reads are automation stops. Boolean properties, text, value, and current URL execute only the closed v7 operators and property forms. The runner rechecks frame/scope and target count after a read so detected drift cannot turn an unevaluable read into an assertion failure.

An evaluated true predicate records `QA_ASSERTION_PASSED`; an evaluated false predicate records `QA_ASSERTION_FAILED` for that deterministic step. These step outcomes are inputs to later two-run classification, not a terminal public QA result on their own. Invalid scope/frame, ambiguous target, unsupported property, browser/query failure, and malformed artifacts stay in non-QA failure categories. A failed assertion blocks subsequent dependent steps in that run. No assertion is inferred from authored prose, and no exploration observation value substitutes for the fresh browser read.

WP5A does not add production orchestration, result projection, or public protocol changes. The handoff is to route accepted v7 artifacts through two independent fresh executions under the same effective profile, then apply reviewed agreement and terminal ResultRecordV2 classification. A live approved-public target and protected-service run remains an environment release gate.
