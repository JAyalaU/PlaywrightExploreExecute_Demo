# P4-G0 decision: sanitized live events

Status: **complete for P4-1 implementation**. This is a decision contract, not an implemented feature. It closes the P4-G0 gate in the [Phase 4 plan](phase-4-implementation-plan.md). The existing [subprocess protocol v1](p2-3-subprocess-protocol.md) remains one final JSON document on stdout. [Report projection v1](p3-b-report-projection.md) remains a separate, post-run, read-only exchange. Neither contract gains event frames or new fields.

## Selected boundary and transport

The trusted Python host creates one IPv4 `127.0.0.1` TCP listener on an OS-assigned port immediately before it launches one Node child. It generates a random 256-bit, single-use capability and a random UUID stream ID. It passes the listener port, stream ID, and capability to that child only through trusted launch environment variables, never through task JSON, command-line arguments, stderr, Streamlit state, an artifact, or the browser container. The child connects once, sends one bounded JSON-line `hello` containing `eventStreamVersion: "1"`, the stream ID, and capability, and waits for the host's matching `ready` acknowledgement. The host verifies the capability with a constant-time comparison, accepts only one authenticated connection, and closes the listener. An invalid, duplicate, late, or non-loopback connection is rejected. The Node child erases the capability from its process environment after the handshake. The existing Chromium launch-environment allowlist must exclude all event-channel variables.

The host starts draining the event socket, stdout, and stderr concurrently. Only the event socket carries live execution facts. Stdout retains exactly one subprocess-v1 response; stderr remains diagnostics and is never parsed into engine progress. The host owns the listener, authenticated socket, receiver, child supervision, and teardown. Node owns event construction and sequence. This private, one-run channel is neither a browser endpoint nor a general engine API. It does not listen on an external interface. A 5-second Node connect/ack timeout and a 15-second host accept/handshake timeout apply within the existing host deadline; neither is task-controlled. Node attempts a bounded event flush of at most 250 ms after constructing its terminal event and before writing final stdout. After the child exits, Python drains to event-socket EOF, waiting at most 500 ms within the existing host deadline, before reconciling the timeline. Cancellation or deadline closes the socket/listener immediately and reaps the child under the existing rules.

Frames are UTF-8 JSON objects terminated by one LF. The handshake is not an execution event. Every event frame is at most **2,048 bytes including LF**; each stream emits at most **256 frames and 256 KiB total**. Duplicate JSON keys, unknown fields, invalid UTF-8, embedded line breaks, and incompatible versions are rejected. Node uses one central, nonblocking, bounded writer with at most **32 queued frames or 64 KiB**. Its observer callbacks cannot await socket drain, throw into the engine, mutate execution state, or alter the final response. The Python receiver continuously drains and validates frames independently of Streamlit rendering. The UI may display at most the latest **128** validated events; if it omits older events it labels the omitted count. There is no disk spool or replay/resume endpoint in P4-1.

## Closed event contract

Each event has exactly these envelope fields: `eventStreamVersion: "1"`, `streamId` (the handshake UUID), `sequence` (integer 1–256), `occurredAt` (UTC RFC 3339 timestamp with milliseconds), `kind` (the closed discriminator below), and `context`. `context` is a closed object: required `testSpecId`, `executionProfileRef` (`id`, `version`), and `profileFingerprint`, plus only the IDs relevant to the event: `explorationAttemptId`, `resolvedSpecId`, `executionRunId`, `originStepId`, `executionStepId`, `locatorId`, and `mcpCallId`. The identifier and fingerprint syntax/length are those of subprocess v1. For a pre-work `bridge_error` terminal, `context` is `null`; no TestSpec or profile is invented. Each event also has exactly one `data` object of the shape specified for its kind. No arbitrary string/map extension field exists. A derived display/event key is `(streamId, sequence)`; it is a correlation key, never an image, viewer, report, or evidence access capability.

| `kind` | Allowed `data`; required context additions | Emission point |
|---|---|---|
| `workflow_started` | Empty object; base context only | After trusted request/profile/public-target preflight, model configuration, and TestSpec ID creation; always sequence 1 for a started workflow. |
| `interpretation_started` | Empty object; base context | Before the bounded interpretation call. |
| `interpretation_finished` | `outcome: accepted \| stopped`; base context | After existing interpretation validation. No model text. |
| `exploration_started` | Empty object; attempt ID | When M6 creates the attempt. |
| `step_decision_started`, `step_decision_finished` | Empty object; attempt and origin-step IDs | Around an M7 step decision. The final result supplies any failure classification. |
| `mcp_tool_started` | `tool` from the eight-name allowlist below; attempt and generated MCP-call IDs | Immediately before the permitted MCP call. |
| `mcp_tool_finished` | `tool` and `outcome: completed \| failed`; attempt and matching MCP-call IDs | After the same call. No arguments, response, or error text. |
| `locator_assessed` | `outcome: accepted \| rejected`, `basis: mcp_generated \| semantic_row_scope`, and `reasons` (0–5 distinct quality codes); attempt, origin-step, execution-step, locator IDs | After the deterministic locator gate. Accepted means the reviewed form passed its own gate; a rejected raw MCP expression remains rejected even if a separately verified semantic row scope is accepted. |
| `resolved_spec_ready` | Empty object; attempt and resolved-spec IDs | After the resolved spec is validated and stored. |
| `replay_started` | `ordinal: 1 \| 2`; attempt, resolved-spec, and run IDs | Before each fresh deterministic replay. |
| `replay_finished` | `ordinal: 1 \| 2`, `status` from `ResultStatusSchema`; attempt, resolved-spec, and run IDs | After that run's typed outcome is recorded. Select the run-level status using the existing automation/QA precedence, never a trailing `NOT_RUN` placeholder. |
| `report_completed` | `availability: available \| unavailable`; base context and whichever attempt/resolved IDs exist | After Node verifies the report state. No report path/reference. |
| `stream_truncated` | `cause: event_limit \| byte_limit`; same base context | Once, after the operational-event cap; later intermediate events are omitted. Terminal remains eligible. |
| `terminal` | Exactly one of `{resultKind: success, phase, status, reason?}`, `{resultKind: typed_stop, stopKind, phase, status, reason?}`, or `{resultKind: bridge_error, code, cleanup}` using subprocess-v1 closed fields; context mirrors the final v1 result where one exists | Once after the final v1 response is constructed, before stdout is written. It is a preview, not QA authority. |

The MCP allowlist is exactly `browser_navigate`, `browser_snapshot`, `browser_find`, `browser_generate_locator`, `browser_click`, `browser_fill_form`, `browser_select_option`, and `browser_wait_for`, from the current M6 wrapper. Locator rejection reasons are exactly `UNSUPPORTED_GRAMMAR`, `WEAK_IDENTITY`, `TEST_ID_PROVENANCE_UNVERIFIED`, `NON_UNIQUE_MATCH`, and `TARGET_MISMATCH`. Terminal phases, statuses, safe reasons, bridge codes, cleanup, and profile/ID forms reuse the current closed subprocess-v1 vocabularies. An unknown stored reason is emitted only as `REDACTED_REASON`; it is never forwarded verbatim. The producer and consumer each reject any other value. No raw provider error may become a `data` field.

## Ordering, consistency, and loss

Node assigns sequence numbers at a single producer point, beginning at 1, in emission order. Python requires strictly consecutive numbers and matching stream ID, TestSpec ID, profile reference/fingerprint, established attempt/resolved/run identities, and paired MCP-call IDs/tool names. It never sorts by timestamp or derives a missing step from elapsed time. Replays have distinct run IDs, ordinal 1 before ordinal 2, and neither may precede `resolved_spec_ready`. The final `terminal` agrees with the validated subprocess-v1 result, including its progress/report correlations and exit code; the **v1 result wins** if an event is missing or contradictory. Python then marks the timeline `unavailable` or `inconsistent`, withholds the affected timeline, and retains the original typed QA or process outcome. A valid terminal event is not required to trust a valid v1 result.

Node reserves two frames and **4 KiB** for `stream_truncated` and `terminal` after at most **254 operational events or 252 KiB of operational frames**. A stream truncated at a cap visibly omits intermediate stages; it never fabricates completion. If socket backpressure exceeds the bounded writer, a write fails, the socket closes, or Python detects a malformed, oversized, duplicate, out-of-order, or wrong-stream frame, the receiver marks observation `unavailable` and shows only validated prior events with an explicit interruption marker. It does not infer events from stderr, report artifacts, or the final envelope. The final v1 result is still read normally. An event-transport fault **after engine start** cannot reclassify QA or grant authority; Node abandons further event writes without blocking execution. A socket/handshake/security failure **before engine start** fails closed with an existing `bridge_error` code `WORKFLOW_FAILED`, `cleanup: not_started`, or, if Node cannot produce that response, the existing host `process_failure`. No new subprocess-v1 result variant is introduced.

Explicit UI cancellation signals the existing Python host cancellation path; it closes the event channel and terminates/reaps the Node child under the existing process rules. Forced termination continues to report cleanup as `unverified`. Streamlit rerenders use the same single active host call and validated in-memory event buffer; they never launch a duplicate child. The UI polls the host buffer while the call runs and displays a live timeline without blocking its refresh on the final synchronous call. If the UI viewer disconnects, the host continues the one already bounded run to its final result or deadline; browser-tab closure is not claimed as a reliable cancellation signal. Host shutdown closes the channel and applies existing child termination. A new run receives a fresh stream ID and capability; events from an old run cannot attach to it.

## Security and ownership

Events are built only from trusted control-flow branches, enum constants, validated result records, and generated IDs. The event sink is not passed raw MCP records or provider responses. Prohibited fields include private model reasoning, prompts/output, task text, URLs/query strings, arbitrary page text/snapshots, selected refs, locator expressions, MCP arguments/results, raw exception messages, credentials, hashes, artifact paths/references, and evidence bytes. Python validates the complete closed event, sequence, and correlation before adding it to the UI buffer. Streamlit renders reviewed labels/codes and cannot classify QA or amend the final outcome. The local loopback listener and capability protect the channel against accidental or unrelated local connections; they do not claim isolation from malicious code already running as the same operator identity. The isolated browser receives neither endpoint/capability nor access to this host channel.

P4-2 may use `(streamId, sequence)` and the validated attempt/run/profile IDs to align frame availability with this timeline. P4-3 may use the same IDs for viewer lifecycle labels. Neither receives access authority from an event ID; image and viewer authorization require later, separate reviewed gates.

## Implementation handoff and verification

- **P4-1A — AI engineer/Node specialist:** implement the closed TypeScript schema, central safe producer, stage instrumentation, and final-result reconciliation hook. Keep observer failure isolated from runner/model/QA behavior. Verify a normal full run, an interpretation/locator stop, and an injected page/MCP payload that cannot enter a frame.
- **P4-1B — Python host integrator with Node subprocess owner:** implement the host-created authenticated loopback channel, Node connector/framing, compatible closed Python validator, concurrent draining, single-run in-memory buffer, Streamlit polling/timeline, explicit cancellation and cleanup. Verify normal incremental delivery, malformed/unauthorized connection, after-start disconnect, truncation, deadline, and v1 stdout compatibility on Windows and the supported local runtime.
- **P4-1C — Test automator and security reviewer:** exercise the test-only injected-model subprocess path and exact-profile protected browser, plus a human-operated real-provider UI run. Compare the timeline's terminal and correlation to the validated v1 result and reconstructed report. The manual gate remains unverified until a real credentialed run is observed.

Security review of the implemented field allowlist, token handling, browser-environment exclusion, and fail-closed preflight is required before P4-1 release. No production code changes were made by this decision gate.
