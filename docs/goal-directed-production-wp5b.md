# Goal-directed production orchestration (WP5B)

`goal-directed-v1` is a trusted launch selection. The request wire does not select it. The local Python host passes the selected version to the Node subprocess environment, and Node fixes that version before interpretation. The released `agentic-exploration-v1` route remains on TestSpec v2/v3, trace v2, compiler v1, and resolved v6. The new route uses TestSpec v4, the M7 v3 action controller plus M7 v4 verification decisions, trusted WP2 observations, trace v3, compiler-attempt v2, and resolved v7. Neither route falls back to the other.

The goal-directed exploration controller preserves the released action candidate/binding/observation budgets and separate diagnostic branches. It attaches a WP2 observation session and WP3A strategy controller to the same protected attempt before a v3 assembler subscribes to observations. Each evaluated `verification_goal` is appended at its authored position. After a verification observation, the action snapshot is refreshed before selecting transient MCP refs; current-state bindings still authorize actions. A changed-state failed action after a recorded verification stops unresolved because fresh-session recovery cannot safely transplant prior observation strategies. Action-only recovery retains the released reconstruction path. Only a complete ordered v3 path is stored.

The v3 compiler opens a separate protected context. An accepted v7 artifact is executed twice by `executeAndStoreAgenticRunV7`; each call opens and closes its own fresh protected context, persists a run linked to the accepted v3/compiler-v2/v7 chain, and uses no LLM or MCP. Matching completed deterministic signatures produce `QA_ASSERTION_PASSED` or `QA_ASSERTION_FAILED`. A false exploration observation does not itself set QA. Differing replay signatures, including completed versus automation failure, stop at reproducibility. Matching automation failures and environment failures remain non-QA.

`ResultRecordV2` and report projection v2 accept either explicit workflow value while preserving the same public stage/status/reason taxonomy. Finalization and projection branch on the recorded workflow, read the matching trace/compiler/resolved namespace, verify source/profile/attempt/trace/compiler/resolved/run linkage, and expose only reviewed safe fields. Compiler-v2 unsupported reasons are projected as the reviewed public `UNSUPPORTED_CAPABILITY`; raw strategy and observation records remain private. The v7 runner's private `VERIFICATION_FALSE` reason maps to public `REDACTED_REASON` on QA failure.

The non-provider protected fixture covers Add/Remove true and false, two replay disagreements, equivalent automation stops, temporal compilation unsupported, unresolved exploration, provenance/version rejection, separate context cleanup, no MCP below accepted v7, and the local interpretation-to-terminal route. A separate independent release gate should run the complete compatibility suites and the reviewed protected-service/approved-public-target proof. No credentialed provider workflow was required for this implementation package.
